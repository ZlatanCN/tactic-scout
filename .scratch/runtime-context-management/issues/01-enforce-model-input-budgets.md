# 01: 所有模型入口先做完整请求预算检查

Status: resolved
Blocked by: None (can start immediately)
Parent: [运行时上下文管理](../spec.md)

**What to build:** 球探的小请求继续走正常业务路径；所有现有模型入口在发送前采用完整请求预算与有限输出上限。模型窗口未知或预算配置无效时，应用明确停止，不把原结果丢弃或把未完成解释说成完成。

## Acceptance criteria

- [x] 请求理解、lookup 工具循环、执行 / 保存结果解释都采用同一准备请求契约，实际 API 请求带有限输出上限。
- [x] 显式配置优先；可信模型资料与自定义网关边界正确，未知窗口在网络调用前明确失败。
- [x] 系统消息、工具调用 / 结果、工具 schema、结构化输出 schema 和协议开销均计入估算；余量和独立 / 共享窗口计算正确，无重复输出扣除。
- [x] 80% / 60% 可配置；硬超限返回明确的待处理 / 不能继续状态，基础指令过大与用户输入过大分别报告，必要信息不为达到 60% 被丢弃。
- [x] 新的硬停止发生在完整已验证数据提交后时，完整呈现已保存数据与来源并标解释未完成；确定性读取证据与模型输入证据分别记录。自动分批展示由后续业务票扩展。
- [x] 从引入有限输出上限起就保留终止元数据，明显截断或不完整结构化输出不被消费为完成请求 / 答案，草稿不冒充最终结果。自动续写 / 重分批由 10 交付。
- [x] 小请求通过原有身份解析、确定性工作流和 saved reuse，零辅助模型调用，原完整快照 / Store 权威保持。
- [x] 准备调用边界的抽取不重置原物理请求上限、一次提取修复或独立三次搜索计数；已有真实请求 / 重试回归观察网络调用次数。
- [x] 通过完整图与本地捕获请求验证真实输出参数及工具 / 结构化 schema 负载；测试配置从既有图工厂入口注入，预算日志不包含原始提示 / 阵容。
