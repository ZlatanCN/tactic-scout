# 11: 额度耗尽后明确继续并跨重启续接

Status: open
Label: ready-for-agent
Blocked by: 02, 04, 07
Parent: [运行时上下文管理](../spec.md)

**What to build:** 长任务仅因上下文处理额度耗尽而停下后，球探可以明确要求继续，从持久化断点获得一份新的有界额度；正常重启、重复恢复和 cache 变化不会造成重复拨款或重做已完成计算。

## Acceptance criteria

- [ ] 只有额度耗尽且原线程 / 请求 / 来源进度仍有效时新增 grant；继续消息 / 确认 ID 幂等，累计历史消耗保留，普通恢复 / 重启不拨款。
- [ ] 配置、鉴权、契约错误或条件歧义不能靠继续绕过；多个可能目标仍澄清，新任务不能串用另一项任务的额度 / 摘要 / 进度。
- [ ] 已完成数据和原日期直接复用，不再次调用 provider / ranker，除非用户明确要求刷新。
- [ ] 分别从 04 的未处理完长指令和 07 的已完成推荐数据 / 未完成解释断点续接，验证部分理解与数据复用两种实际路径；共用 03 的 grant / 停止状态契约，不依赖 09 / 10 才能区分拨款资格。
- [ ] 重复 compaction 与多个 grant 后，原文引用、精确条件、参与者和 source / scope 仍保持；缓存内容 / digest / 版本失效时从原文重建，不仅反复概括旧摘要。
- [ ] 真实 Dev Server 隔离存储场景覆盖正常重启、pending clarification、源输入 / 缓存改变、未知完成状态保守结算、主 State 不兼容与辅助缓存重建的区别。
- [ ] 验证用户等待 / 停机不按墙钟累计、恢复不清零、首次 / 重复继续的准确拨款、完整数据与解释状态，并通过长线程和固定证据续接评测检查实际任务成功与漂移。
- [ ] 延续前票已有的恢复验证；本票交付的是明确继续与跨阶段长任务续接，而不是最后才补持久化 / 观测测试。不访问或清理用户真实持久化存储。
