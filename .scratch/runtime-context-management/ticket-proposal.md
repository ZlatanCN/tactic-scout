## 01：所有模型入口先做完整请求预算检查

**What to build:** 球探的小请求继续走正常业务路径；所有现有模型入口在发送前采用完整请求预算与有限输出上限。模型窗口未知或预算配置无效时，应用明确停止，不把原结果丢弃或把未完成解释说成完成。

**Blocked by:** None (can start immediately).

**验收条件：**

- [ ] 请求理解、lookup 工具循环、执行 / 保存结果解释都采用同一准备请求契约，实际 API 请求带有限输出上限。
- [ ] 显式配置优先；可信模型资料与自定义网关边界正确，未知窗口在网络调用前明确失败。
- [ ] 系统消息、工具调用 / 结果、工具 schema、结构化输出 schema 和协议开销均计入估算；余量和独立 / 共享窗口计算正确，无重复输出扣除。
- [ ] 80% / 60% 可配置；硬超限返回明确的待处理 / 不能继续状态，基础指令过大与用户输入过大分别报告，必要信息不为达到 60% 被丢弃。
- [ ] 新的硬停止发生在完整已验证数据提交后时，提供最小的完整数据 / 来源展示（必要时分段）并标解释未完成；不只提示“结果已保存”。确定性读取的证据从首次展示起正确记录，后续业务票扩展各自展示规则。
- [ ] 从引入有限输出上限起就保留终止元数据，明显截断或不完整结构化输出不被消费为完成请求 / 答案，草稿不冒充最终结果。自动续写 / 重分批由 10 交付。
- [ ] 小请求通过原有身份解析、确定性工作流和 saved reuse，零辅助调用，原完整快照 / Store 权威保持。
- [ ] 准备调用边界的抽取不重置原物理请求上限、一次提取修复或独立三次搜索计数；通过已有真实请求 / 重试回归观察网络调用次数。
- [ ] 通过完整图与本地捕获请求验证真实输出参数及 schema 负载；测试配置从既有工厂入口注入，预算日志不包含原始提示 / 阵容。

**规格用户故事：** 1, 2, 24, 25, 30, 35, 36, 38, 39, 40, 41, 42, 45, 49, 56, 58, 59, 61, 62。

**Blocked by:** 01。

**验收条件：**

- [ ] 无关别名 / 持久化旧聊天不再全量进入模型；本轮明确提及、已有 focus、有效条件及所需已解析引用得到保留。
- [ ] 名称规范化沿用既有规则，不通过近似姓名、最近记录或摘要新建 / 合并身份。

## 03：一次自动文字压缩后完成任务并记住额度

**What to build:** 实际将进入模型的文字使业务请求装不下、但待压文字能放入一次辅助请求时，应用自动生成可核对的 Compacted scouting instruction / 文字摘要并继续真实任务。首次辅助调用就受到可恢复额度约束。

**Blocked by:** 01。

**验收条件：**

- [ ] 打通一个真实业务入口的自动文字处理闭环；本轮原文能在旧内容缩减后装下时保留原样，不将原本未使用的历史重新全量注入。
- [ ] 默认沿用任务模型 / 端点，独立压缩模型可显式配置并验证自身预算；待压源文字超出辅助请求预算时不递归盲发，明确保留进度供后续分块路径处理。
- [ ] 原文、精确任务锚点和引用保留并校验所支持的确切条件，摘要不能确认身份或取代原始请求；JSON 合法不等于语义完整，条件不明确仍澄清，截断 / 失败不把不完整草稿写成成功请求。
- [ ] 第一个新增调用前即 checkpoint 预留；共享 grant 默认 6 次 / 120 秒，失败 / 重试、活动时钟、取消、原有三次请求 / 三次搜索限制和稳定操作分类一起生效。
- [ ] 压缩元数据和公共来源 / 覆盖观测契约随线程保存；复用时匹配源消息 / 范围、内容 hash、依赖结果 digest、原请求及适用模型配置 / 格式版本。不匹配则从原文重建，不能仅凭缓存存在就复用。
- [ ] 正常重启可复用有效缓存；原请求恢复不清零，不因新图步骤重新获得原业务三次请求额度，未知完成状态保守结算；辅助缓存失效不拒绝整条线程。
- [ ] 验证真实图任务结果及至少一条真实 Dev Server 正常重启路径；小请求不走辅助流程，内部摘要不作为最终聊天回答，原有成功快照 / 身份 Store 保持。

## 09：provider 实际输入溢出自动缩减恢复

**What to build:** 即使本地预算检查通过，provider 仍报告 context-overflow 时，系统利用各入口已有的文字 / 证据处理策略自动缩减后有限重发；不能恢复时保留成果并真实交付。

**Blocked by:** 04, 05, 06, 07, 08。

**验收条件：**

- [ ] 可识别输入 overflow 与鉴权、配额、配置及普通暂时故障分类正确，后者不进入 compaction 重试。
- [ ] 原业务恢复请求同时消耗额外额度和原操作尝试次数；辅助请求及其重试也按既有分类记账，重新进入节点不刷新预算。
- [ ] 每次恢复后的 payload 有明确缩减进展并满足准备请求检查；无可缩减内容或无进展时退出，不相同内容盲重试。
- [ ] 文本分块、lookup、比较和两类推荐入口均使用自身已完成的缩减策略，保护精确约束、tool pairing、完整来源及覆盖。
- [ ] 在额度 / 时间内完成则交付原任务；耗尽或不能恢复时走本工作流已有完整数据 / 未完成出口，取消及时停止。
- [ ] 扩展现有本地 fake gateway 验证实际请求 / finish / usage 和计数；记录估算与 provider usage 的区别，不记录原始提示 / 阵容。
