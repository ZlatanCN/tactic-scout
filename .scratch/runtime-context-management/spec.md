# 运行时上下文管理

Status: resolved

设计确认：2026-11-08，Q1–Q16。本规格及实施票据 01–11 已完成。

## Problem Statement

球探在持续查询、比较和推荐球员时，当前请求、线程别名、工具结果或一条很长的用户消息可能超出模型输入窗口。现有流程会按用途组装输入，但没有统一的 token 预算、自动 compaction 或上下文溢出恢复；模型输出被截断时，也不能据此认为全部球员或候选都已解释完毕。

仅保存聊天记录和完整结果不能解决这个问题。用户需要在正常请求不被额外拖慢的同时，自动处理长输入和大结果，并在开销受控、事实可核验、原始证据可恢复的条件下继续任务。已经完成的数据、明确确认的身份和既有成功快照不能因压缩或解释失败而丢失或被改写。

## Solution

在现有 StateGraph 中增加共享的运行时上下文管理能力，覆盖请求理解、lookup 工具循环、执行及已保存结果解释，以及新增的摘要、分块和恢复调用。程序按工作流选择证据、安排分批和原文回读；结构化球员事实保持精确，文字过程和旧对话可以摘要。

系统在每次模型调用前核对完整请求预算。默认在可用输入预算的 80% 触发 compaction，以 60% 为压缩目标；本轮消息自身过大时也自动分块处理。压缩结果、证据覆盖、进度和额度随线程恢复，完整原始材料继续保留。默认每个请求允许最多 6 次额外模型调用和 120 秒累计活动处理时间，均可配置。

完整数据已经生成但解释未完成时，用户仍获得程序生成的完整数据及来源，并看到解释未完成的说明。任务理解或数据本身不完整时，不给出整体比较或排名结论。仅因额度耗尽而停下的任务，可在用户明确要求继续后追加新的有界额度，从断点续接。

## User Stories

1. 作为球探，我希望所有需要模型参与的工作流都有输入预算检查，以便查询、比较、推荐和追问都能获得一致的上下文保护。
2. 作为球探，我希望普通小请求沿用直接处理路径，以便不为无需压缩的任务支付额外摘要调用成本。
3. 作为球探，我希望长对话仍保留当前球员焦点和有效任务条件，以便后续代词和条件细化不会指向错误对象。
4. 作为球探，我希望大工具结果自动被选择和分批处理，以便不必仅因数据量大就重新提出同一个任务。
5. 作为球探，我希望第一条用户消息本身过长时也能自动触发 compaction，以便长输入不依赖已有历史才能被处理。
6. 作为球探，我希望本轮消息在压缩旧内容后能够装下时保持原文，以便减少对最新要求的改写。
7. 作为球探，我希望超长指令中的全部球员、团队和参考对象都得到保留，以便任务不会静默遗漏参与者。
8. 作为球探，我希望排除对象和否定条件在分块后仍然准确，以便系统不会推荐我明确排除的人选。
9. 作为球探，我希望日期、赛季、赛事、位置、数值和单位保持准确，以便压缩不改变筛选及比较范围。
10. 作为球探，我希望跨块指代和后文对前文条件的明确修正被正确合并，以便最终执行的是完整输入表达的要求。
11. 作为球探，我希望真正矛盾或不明确的条件仍触发澄清，以便自动压缩不会替我猜测业务决定。
12. 作为球探，我希望压缩后使用的证据保留精确来源和记录身份，以便能核对每个事实来自哪里。
13. 作为球探，我希望未放入模型输入的字段与来源明确缺失的字段被区分，以便字段选择不会产生错误的缺失声明。
14. 作为球探，我希望来源未查询、不可用和返回空结果继续具有不同含义，以便回答不会夸大一次查询证明的事实。
15. 作为球探，我希望 FM 能力快照与 Understat 表现范围保持分离，以便压缩不把快照数据说成当前比赛表现或注册信息。
16. 作为球探，我希望多人比较保留所有参与者和各 scope 的覆盖说明，以便局部可比范围不会被说成全体共同范围。
17. 作为球探，我希望能力相似候选完整保留原排名，以便分批解释不会遗漏或重新排序已计算的结果。
18. 作为球探，我希望高潜名单作为独立列表完整保留，以便它不会与能力相似度混成一个未经定义的排名。
19. 作为球探，我希望参考画像、年龄计算日期、FM 日期和筛选阶段计数保持清楚，以便能正确解释推荐结果。
20. 作为球探，我希望球队推荐保留阵容获取日期、映射覆盖、实际参考对象和 rankingBasis，以便不会把身份映射数量误解为位置适配人数。
21. 作为球探，我希望 lookup 继续使用已解析的精确来源 ID，以便压缩不会允许模型换成同名球员。
22. 作为球探，我希望已保存结果的追问继续读取原快照，以便不会为了恢复上下文而重新查询 provider 或重新排名。
23. 作为球探，我希望系统能够准确区分已处理和剩余内容，以便局部处理不会被呈现为全部完成。
24. 作为球探，我希望完整数据已有而解释尚未完成时仍能看到完整数据和来源，以便已完成的计算不会因解释失败而失去价值。
25. 作为球探，我希望理解或数据本身不完整时只收到真实的进度与限制，以便不会据不完整材料得到整体比较或排名结论。
26. 作为球探，我希望明确要求继续后从断点和已有数据续接，以便不重复已经完成的查询、排名和处理。
27. 作为球探，我希望重复提交同一继续请求不会重复增加额度，以便恢复操作的成本保持可控。
28. 作为球探，我希望普通重启和中断恢复不会自动增加额度或启动任务，以便系统活动符合我的明确请求。
29. 作为球探，我希望配置、鉴权、契约或条件错误不能被一句继续绕过，以便自动恢复不会重复无效操作。
30. 作为球探，我希望完整原文和已验证工作流结果保持可追溯，以便压缩后仍能核对或读取先前未选择的信息。
31. 作为返回同一线程的球探，我希望正常重启后恢复压缩结果、覆盖范围和处理进度，以便长任务能够继续。
32. 作为返回同一线程的球探，我希望过期或不匹配的压缩缓存从原文重建，以便不会复用属于另一份输入的摘要。
33. 作为球探，我希望多次压缩后仍遵守早期精确约束，以便任务不会逐轮漂移。
34. 作为球探，我希望上下文摘要不创造跨线程身份确认，以便压缩结果不会改变我的 user-confirmed player memory 或共享 Reep 关系。
35. 作为维护者，我希望可以按端点、模型和用途明确配置预算，以便适配当前模型和自定义网关。
36. 作为维护者，我希望未知模型窗口在调用前要求配置，以便系统不会按模型名称猜测一个不可靠的大窗口。
37. 作为维护者，我希望压缩默认使用当前任务模型，同时可独立配置压缩模型，以便在经过验证后调整压缩成本和能力。
38. 作为维护者，我希望各用途有实际传给 API 的有限输出上限，以便输入预算中的输出预留具有真实依据。
39. 作为维护者，我希望计数包含系统指令、工具和结构化输出 schema 等完整请求内容，以便只数聊天正文不会低估负载。
40. 作为维护者，我希望总窗口与独立输入、输出上限的语义被区分，以便不会遗漏输出预留或重复扣除它。
41. 作为维护者，我希望软触发线、压缩目标和硬检查分别配置，以便既提前整理上下文，也不为达到目标而丢弃必要信息。
42. 作为维护者，我希望计数的估算性质被说明，并能处理 provider 实际返回的 overflow，以便计数差异不导致无界失败重试。
43. 作为维护者，我希望辅助摘要和分块调用也必须符合输入预算，以便压缩器本身不会再次接收同一份超限输入。
44. 作为维护者，我希望额外调用数和累计活动时间有统一上限，以便多节点处理不会不断放大成本与等待时间。
45. 作为维护者，我希望既有节点重试、结构化输出修复和 lookup 搜索上限继续有效，以便新上下文流程不削弱原有 fault tolerance。
46. 作为维护者，我希望失败、重试和恢复后的调用仍保留其分类与消耗，以便重新进入节点不会刷新已用预算。
47. 作为维护者，我希望模型价格未知时记录调用与 token 用量，以便不以不可靠的金额估算冒充精确费用控制。
48. 作为维护者，我希望输入溢出与鉴权、配额、配置错误被分别处理，以便只对能够通过缩减恢复的情况进行 compaction。
49. 作为球探，我希望输出被截断时不会被当作完整答案，以便全部参与者和候选的交付状态真实可靠。
50. 作为球探，我希望取消、超时和活动额度耗尽能及时停止新增调用，以便停止请求后不会继续消耗模型额度。
51. 作为维护者，我希望首版由程序按现有工作流安排证据读取，以便不引入未经约束的通用上下文检索工具。
52. 作为球探，我希望原文回读使用保存的精确引用，以便恢复遗漏信息时不会凭摘要重构来源事实。
53. 作为维护者，我希望缓存有效性校验绑定消息、内容、结果和版本，以便模型或任务改变时不会串用压缩结果。
54. 作为维护者，我希望模型不能自行选择预算拨款或记忆命名空间，以便额度与身份记忆的控制仍由应用负责。
55. 作为维护者，我希望外部调用前先持久化预留，并对未知完成状态保守结算，以便重启不能让已开始的调用免费重做。
56. 作为维护者，我希望通过完整图调用观察功能行为，以便验收不依赖私有 helper 的调用顺序或内部结构。
57. 作为维护者，我希望复用真实 Dev Server 的隔离测试入口验证恢复，以便不把 SDK 内存测试误当成服务持久化证明。
58. 作为评估者，我希望模型收到的证据与程序直接渲染的证据分别记录，以便判断事实依据时不会误认模型看过完整存储结果。
59. 作为维护者，我希望观测包含预算来源、压缩前后规模、覆盖和实际 usage，但不写原始提示或阵容数据到普通日志，以便能诊断问题并保持现有日志边界。
60. 作为评估者，我希望通过压缩后的继续执行检查任务、条件和事实是否保持，以便更短的摘要不会被错误认定为正确摘要。
61. 作为球探，我希望内部摘要、分块草稿和进度不会冒充最终回答，以便清楚知道哪些结果已经可以使用。
62. 作为维护者，我希望新功能与已完成的 checkpointer、Store、schema 兼容性和 native interrupt 行为整合，以便现有线程恢复和身份记忆保持正确。

## Implementation Decisions

- 保留现有 StateGraph、必经身份解析和澄清、确定性比较与推荐、四类 active workflow snapshot 及其 resultJson 表示。共享上下文管理能力统一处理预算、自动 compaction、调度和恢复，各业务入口提供自己的证据选择规则。
- 模块边界沿用项目约定：图入口负责组装，实际节点负责 State patch，共享能力以用途命名，player-data 不依赖图 State。首版不迁移到其他 Agent harness，不新增通用模型驱动检索工具或独立文件系统。
- 扩展现有图工厂的依赖注入契约，支持运行时预算 / 能力配置、可选独立压缩模型，以及在必要时用于确定性时间验收的活动时钟。准备结果明确区分可调用、需自动处理和不能继续，并携带覆盖、引用、预算及停止原因。
- 预算按端点、模型及调用用途解析。显式配置优先，可信标准端点可采用已知模型资料；未知窗口或无法确认限制的自定义网关在调用前报告配置错误。
- 每类调用必须解析出有限的输出上限并实际用于模型请求。可继承已有明确配置；未知的 provider 默认输出额度不能视为零。任务模型和独立压缩模型分别验证能力及预算。
- 计数覆盖完整实际请求，包括系统指令、全部消息、现代工具调用与结果、工具 schema、结构化输出 schema 和协议开销。优先采用模型 / 协议适配的本地计数；只能估算时注明方法并要求正的误差余量。
- 共享窗口已知时先预留本次输出，独立输入上限已知时同时取其约束，再扣除计数余量；独立输入限制不能重复扣除已分离的输出。预算必须为正，基础指令与必要 schema 装不下时属于配置或请求构造失败。
- 使用可配置的初始比例：可用输入预算的 80% 软触发，60% 为压缩目标，每次发送前另做硬检查。必要内容完整且符合硬上限时允许高于 60% 继续；没有缩减进展时不得反复压缩。比例需要边界用例调优，不视为测量保证。
- 触发依据是本次实际模型输入。原本不进入模型的旧持久化历史不因消息总数增长而被重新全量加载到摘要调用。
- 请求理解仅注入本轮所需的焦点、有效工作流条件、参与者和相关已解析别名。精简不能替用户排除仍然可能的续接目标，也不能新建姓名到身份的关系；有歧义仍用既有澄清流程。
- 文字 compaction 保留目标、精确限制、关键 ID、决定、进行中步骤和原文定位。本轮消息在旧内容压缩后能装下时保留原文；自身仍超限时由程序有界分块提取并合并核对。压缩调用自身也经过预算检查，不能递归产生无界摘要。
- 分块合并校验全部参与者、参考与排除对象、否定条件、时间 / 赛季、赛事、位置、数值 / 单位、跨块指代和后文明确修正。引用必须匹配原文。条件不明确或矛盾时保留进度并澄清，不能把各块摘要拼接后直接执行。
- Compacted scouting instruction 是辅助表示，不确认身份、不取代原文，也不能把引用材料提升为更高权限的指令。任意自然语言语义保真不能只靠 JSON 校验证明，需通过续接型评估验证。
- Scouting evidence projection 从 owning schema 验证后的完整结果生成。每批标明原结果引用 / digest、记录引用、所选字段、处理范围和剩余覆盖；模型不能自行换用来源 ID。原始结果与 active snapshot 保持完整，仍先于解释提交。
- 投影区分有值、来源明确 null、字段未选择、来源不可用和来源未查询。省略字段不得成为源数据缺失的证据；canonical 与 unlinked 身份关系、来源状态、请求赛季与实际范围均保留原语义。
- 比较保持全部确认参与者和每个 scope 的 coverage。推荐保持 current 与 potential 两份名单分别完整、原排名、每个候选要求的字段、参考画像、筛选阶段计数及日期。球队推荐额外保留阵容来源 / 时间、映射覆盖 / 方法、实际参考对象、rankingBasis 和排除范围。
- Lookup 保留工具调用与结果的有效配对及 tool_call_id、已解析来源和赛季约束、原始工具内容与搜索限制。投影不删除配对响应，也不把程序回读已存证据算作新的 provider 查询。
- Saved-result reuse 从原完整快照及其日期准备投影，不重新查询或排名。外部数据更新不会自动刷新或改写历史结果；新数据计算才执行现有来源与身份再校验规则。
- 线程辅助 State 保存源消息 / 范围 / hash、结果引用、精确任务锚点、压缩表示及版本、已处理与剩余批次、证据覆盖和预算 grant / reservation / consumption。它属于线程 checkpoint，不写入跨线程身份 Store，也不增加替代既有 request / outcome 续接规则的独立 activeTask 指针。
- 缓存仅在源内容、依赖结果和格式版本仍匹配时复用。被修改、换分支或不兼容的辅助缓存从原文重建；辅助缓存失效不自动使整个线程不可用。主 State 真正不兼容时沿用已完成持久化功能的兼容性规则。
- 摘要和长输入分块默认使用当前任务模型 / 端点，可显式配置独立压缩模型及其窗口、输出额度和计数策略；不能通过未配置的更大模型绕过预算要求。
- 每个用户请求默认有 6 次额外模型请求和 120 秒累计活动处理时间，任一先到即停，均可配置。摘要、分块提取、证据批次解释、中间合并及 context-overflow 恢复引入的请求共用额度，其失败与重试也计数；各次调用仍有输入和输出限额。
- 固定额外调用口径：N 次证据批次解释全部计额外，最终一次原业务回答使用原业务调用预算；若程序直接合成而不再调用最终模型，不能把其中一批改为免计。原业务请求因 context-overflow 缩减后重发的恢复调用，同时消费额外额度和原调用的尝试次数。操作分类与稳定 ID 随恢复保存。
- 原节点最多三次请求、结构化请求至多一次修复、每轮最多三次 lookup 搜索和既有单次 / 外层超时保持。新的图步骤或再次进入节点不能刷新总 grant；实现不得通过不可见循环绕开 checkpoint 及计数边界。
- 外部调用前提交额度预留，完成后按已知结果结算；中断后无法确认完成的已开始调用按预留上界保守结算。允许只读调用重复，不承诺 exactly-once。正常恢复不清零消耗，活动时间不按停机或用户等待期间的墙钟累加。
- 活动时间包括新增选择、压缩、分块、恢复、模型等待与自动 backoff。调用截止时间取原单次超时和剩余活动额度中更短者；取消或耗尽后只做必要的有界提交与确定性交付，不再调用模型。
- Provider 实际 context-overflow 与鉴权、配额、配置和普通暂时故障分别处理。可在剩余额度内缩减 payload 后重发，新 payload 必须有进展；不能把相同超限请求按暂时错误重复发送。
- 输出截断与输入溢出分别处理。检查终止原因、结构化输出及覆盖完整性，有限续写 / 重新分批也计额外额度；截断响应、内部摘要和草稿不能标记为完整 answer 或混作最终聊天回答。
- 完整已验证数据已存在而解释未完成时，由程序完整展示数据和来源，必要时分段并标明解释未完成。理解或数据尚不完整时只说明覆盖与限制，不给出全体比较 / 排名结论；既有成功快照与已提交新数据保留。
- 仅因上下文额度耗尽且原请求 / 进度仍有效时，用户明确要求继续才新增一份有界 grant；来源用户消息 / 确认 ID 保证重复提交幂等，历史消耗保留。普通重启 / 恢复不拨款，配置、鉴权、契约错误和歧义不能用继续绕过。
- 进度、grant 和摘要绑定其线程、原请求及源内容；不能串用于另一项新任务。明确续接时复用已完成数据，不重查或排名，除非用户要求刷新；多个可能目标仍澄清。
- 观测区分完整存储、模型实际收到的证据和确定性渲染直接使用的证据。更新现有 evidence collector 以识别投影 / 批次及覆盖，并兼容原完整结果路径；摘要不成为新造事实或身份关系的权威来源。
- 普通日志记录预算来源、计数方法、输入估算 / 输出上限、前后规模、引用 / 覆盖、停止原因、调用 / 时间消耗和 provider 实际 usage（若有），沿用不记录原始提示及阵容数据的边界。未知价格只报告调用与 token，不作精确金额保证。

## Testing Decisions

- 测试入口沿用 Q16 已确认的最高层应用边界：完整 compiled graph 的 invoke / stream / public State / 同线程 native Command resume。优先从输入、模型实际请求、依赖调用、最终响应和已保存结果验证行为，不断言私有 helper 的调用顺序或内部数据结构。
- 复用现有图工厂的 model / tools / checkpointer / Store 注入，使用隔离 MemorySaver、InMemoryStore、固定来源证据和可控 fake model。新增预算、可选压缩模型及必要活动时钟也在同一工厂入口注入，不新增私有 helper 测试 API。
- 持久化验收复用真实 managed Dev Server 的公开线程 / run / state / resume API 与现有临时项目 / 存储 harness。使用本地 fake HTTP 模型和 provider，正常停止、同存储重启，检查完整上下文、进度、额度、interrupt 与 saved-result reuse。
- 测试先例是现有完整图身份解析、比较 / 推荐、故障注入、快照复用和已完成的 managed-persistence 验收。扩展现有 fake gateway 支持脚本化 overflow、截断终止原因、部分 / 错误结构化响应、取消及响应 barrier；生产 API 不增加测试专用入口。
- 对三类业务模型入口及辅助调用，分别验证完整 schema / 工具计数、有限输出上限、未知窗口配置错误、基础指令过大、80% 触发 / 60% 目标与发送前硬检查。无需处理的小请求不得产生额外摘要调用。
- 使用小测试预算强制覆盖长别名、长历史、首条超长输入、摘要自身过大和多次压缩。验证否定、排除、赛季、数值、跨块指代、后文修正、精确身份和原文引用；歧义必须澄清。
- 覆盖允许的两份各 20 人推荐名单及较多比较参与者，核对完整名单、顺序、必需字段、scope coverage 和 null / omitted / unavailable / unqueried 的不同含义。Saved-result reuse 不调用 provider 或 ranker，历史日期不变化。
- 验证 provider 实际 overflow、鉴权 / 配额等不可压缩错误、输出截断、无缩减进展及辅助调用失败。既有重试上限与新增 grant 同时生效，恢复请求分类和计数保持稳定。
- 使用可控时钟验证 6 次 / 120 秒边界、失败重试记账、取消、保守预留结算和等待排除，避免真实等待两分钟。验证恢复不清零、仅额度耗尽可显式追加 grant、重复继续请求只追加一次，以及续接不重复完成的数据计算。
- 验证完整数据与解释未完成的确定性交付、数据 / 理解未完成时禁止整体结论、原成功快照保持，以及内部摘要 / 草稿不作为最终回答。固定记录可通过程序渲染时，评估记录其真实数据依据。
- 在真实 Dev Server 临时存储中验证正常重启、pending clarification、处理中途未知完成状态、source / cache version 改变、辅助缓存重建与主 State 不兼容的区别。不读取或清理用户真实持久化存储，不以强杀测试推导硬崩溃保证。
- 验证模型实际证据和程序渲染证据的 collector，不能把完整存储一律算成模型已见。结构化正确性由确定性断言检查，任意自然语言保真与重复压缩漂移用固定证据的续接型评测检查，不能只比较摘要长度。
- 实现阶段运行相关现有回归、类型检查和适用静态检查。固定 / fake 验收优先，不为本规格发布运行 live 模型评测；历史 V43 普通案例不作为长输入、20 人名单或溢出恢复已通过的证明。

## Out of Scope

- Checkpoint 历史清理、TTL、存储空间回收或删除原始消息与已验证结果。
- 将压缩摘要变成跨线程用户偏好、身份确认或共享 Reep 链接；修改 Store 的既有记忆权威和删除 / 纠正语义。
- 迁移到其他 Agent harness，新增通用模型驱动文件 / 上下文检索工具、独立文件系统、RAG 或子 Agent 编排。
- 更改来源数据能力、把 FM 快照当作当前注册 / 表现、重新定义推荐排名，或为降低输入量静默改变任务参与者。
- 无上限自动处理、任意长输入必定完成、未知模型窗口猜测、未知价格的精确金额保证，以及 exactly-once 或硬崩溃持久化保证。
- 新建前端、切换部署模式、多用户认证、自动服务启动后执行任务，或扩大原业务来源查询权限。
