# TactiScout 下一条球员数据源候选

研究日期：2026-10-06。先读根目录 `CONTEXT.md`、已有来源研究及 issues 06、09、20、27、32、34、39、42、43、47、48、57、69。以下新增候选只依据各 API / 数据发布方的官方文档、API、许可和代码仓库；没有请求付费 API、下载球员数据或联系供应商。来源页面的覆盖和时效陈述属于提供方声明，不代表独立准确性验证。

## 结论

**FootyStats 是技术字段上最值得继续核实的候选，但本轮没有验证到可用的当前赛季数据，也没有验证生产 entitlement。**官方文档公开列出按赛季分页返回参赛球员、提供方球员/赛季/球队 ID，以及分钟、出场、传球、关键传球、抢断、拦截、盘带、推进传球、xG/npxG/xA、对抗等字段。当前官方测试目录列有 2026/27 EPL 和 Bundesliga 赛季 ID；根任务对公开 `example` key 的 2026/27 EPL 球员列表请求实测得到 HTTP 417，响应消息为 “League is not chosen by the user … League may not exist, or is not available to this user.” 这只证明公开测试 key 不能完成该当前赛季调用；它**不**验证真实账户、免费计划或任何生产 entitlement。另对官方文档示例 2019/20 season ID `2012` 的请求返回 HTTP 200，第一页 200/615 行，但抽样响应仅见基础字段，没有 `progressive_passes` 或 xG。这个样本只覆盖一个赛季第一页，不能反证完整 API 无高级指标；文档字段字典也不能证明公开 demo 响应或任一真实计划会返回它们。未使用用户 API key 或读取当前赛季真实账户数据；历史 demo 页只用于验证该次演示请求的状态、分页和返回字段。[API 概览与计划](https://footystats.org/api) · [赛季参赛球员接口](https://footystats.org/api/documentations/league-players) · [球员赛季指标字段](https://footystats.org/api/documentations/player-individual) · [API 使用条款](https://footystats.org/api/documentations/terms-of-use-and-legal) · [官方公开测试目录](https://api.football-data-api.com/league-list?key=example) · [2026/27 EPL 测试请求](https://api.football-data-api.com/league-players?include=stats&key=example&season_id=17146) · [2019/20 示例赛季第一页请求](https://api.football-data-api.com/league-players?include=stats&key=example&season_id=2012)

**目前没有新增来源同时达到“实时可用、可持久化、可公开展示且确定可进 LLM/RAG”的无条件准入标准。**FootyStats 有最好的候选池与表现字段组合，但公开当前季 key 请求返回 417，生产 access 未验证，条款未定义复制/持久化/RAG 的细节；ASA 有先进指标但未找到数据 license；OpenFootAPI 对自有服务内留存和内部模型研究写得较清楚，但免费档没有球员表现端点；Roanuz 可用但费用较高、统计字段较浅；Impect 的指标更细，不过只有 2023/24 德甲，且 license 限制复制/修改/对外再分发。已选的 Sportmonks 当前池与其模型处理待确认项仍按 [issue 20](../issues/20-licensed-player-provider-and-provenance.md) / [issue 48](../issues/48-sportmonks-current-pool-smoke.md) 处理；本报告不重开已经调查的 StatsBomb、Wyscout、SkillCorner、API-Football、FPL、TheSportsDB、foot.io 或 OpenFootball 决定。

## 候选池与补充证据要分开

- **候选池：**FootyStats 提供当前赛季中已经出场的球员；ASA 可从当前赛事球员表现记录形成参赛池；OpenFootAPI 的 squad endpoint 可能提供俱乐部名单，但公开套餐端点权限还不清楚。三者都没有证据证明覆盖完整转会市场或确认球员可签约。
- **补充证据：**FootyStats 提供赛季累计/每 90 与若干高级统计；ASA 的 xG/xPass/g+ 可带来更有解释力的另一套指标；OpenFootAPI 的 xG 是按球员的射门机会样本；Roanuz 主要是赛事 box score。不同 provider 口径不可直接合并，先按 source ID、联赛、赛季、样本分钟与 field definition 独立保留。
- 本项目可将来源返回的球员记录交给 Agent 或存入案件 checkpoint，因此“API 可读 / app 可显示”不能自动覆盖模型输入和持久化。每一项权限需按当前契约单独登记，遵守 CONTEXT 中的来源许可登记、候选发现、补充证据和历史样本边界。

## 最小实施切片

**FootyStats 的下一步不是写 adapter，而是拿真实账户权限与许可答复，然后再决定是否允许 smoke。**根任务已经用官方公开 `example` key 读取 2026/27 EPL `league-players`，返回 HTTP 417，消息为 “League is not chosen by the user … League may not exist, or is not available to this user.” 对官方示例 2019/20 season `2012` 的请求返回 HTTP 200，但只抽查了第一页 200/615 行，且响应只有基础字段，没有 `progressive_passes` 或 xG；这不能说明剩余页面、单独 player endpoint、付费账户或所有高级字段的行为。不要重复把同一 demo key 当成生产验证，也不要以此推断真实账户一定失败。没有获得 account/plan 许可前，不请求真实当前季玩家行。只有在账户由用户授权配置且条款许可范围得到确认后，才做一页 transient smoke（最多 200 行），只记录脱敏摘要：赛事/赛季 ID、计数、重复 provider ID、位置/球队/分钟覆盖、非空字段覆盖、`last_match_timestamp` 范围和响应时间。不得保存 raw response 或发送给 LLM。

若真实 smoke 后还考虑 adapter，需先确认：

1. EPL 免费 entitlement 是否为可持续使用还是只作 trial，以及真实当前赛季的 endpoints 是否包含于该 plan。
2. 条款中 reproduce/copy 对本机分析所需下载、短暂内存处理、checkpoint/localStorage 缓存的具体适用范围。
3. “public apps/websites and models”是否涵盖本地生成式 LLM prompt、RAG embedding/retrieval 及只展示少量派生事实；原始 API 响应不得转售/再分发。
4. 当前赛季的团队、赛事与球员字段的目标完整度；报告明确标注“本赛季已出场球员”，不把未出场注册球员列为不存在。

若许可答复满足本机持久化、报告展示和预定 AI 处理用途，再按已有 query-scoped contract 接一个独立 `footystats/player-season` 来源：按来源 ID 搜索赛季参赛池、保留来源统计字段和 sample minutes，候选发现与表现评估可共享同一季赛行，但不自动将其他来源统计融合成同一能力分数。若权限无法明确，当前不实现 adapter、不将它登记为可用 Agent source。[按需查询契约 issue](../issues/32-query-scoped-player-source-contract.md) · [来源许可和身份约束 issue](../issues/09-data-source-access-and-provenance.md) · [能力证据覆盖 issue](../issues/57-structured-capability-evidence-coverage.md)
