# 公开足球球探适配排序基准审计

研究日期：2026-10-10。来源访问日期：2026-10-10。

## 结论

在本次检查的公开原始论文、论文数据页和作者项目中，**没有找到同时满足以下条件的可复现基准**：有真实候选球员；有球探/足球专家对候选人的人工判断；判断针对明确的球队招募需求或场上职责；公开完整的 query、候选池、标签及许可；可据此计算 TactiScout 的 query-specific 排序指标（如 nDCG）。最接近的资料分别缺少公开排序判断、具体招募 query，或足够完整的候选级标签。

因此，当前不应用公开事件统计、模型分数、游戏评分、转会结果或合成标签，伪装成球探适配 qrels。项目已有的人工短名单评测应继续为空时返回 `not_evaluable`；未来只在固定 query、完整候选池、双人独立评分和匿名裁决后计算逐 query nDCG@5，符合现有[评测协议](../shortlist-human-judgment-evaluation-refresh-2026-10-10.md)与[项目术语](../../../CONTEXT.md)。

### 必须区分的四类信号

- **比赛事件事实**（传球、射门、对抗等）：可作为能力证据，不是专家适配标签。
- **通用球员评分**（PlayeRank、EA/FIFA 或 Football Manager 属性）：可能是算法、游戏或通用表现刻度，不代表针对本次球队需求的球探判断。
- **真实结果代理**（之后的出场、转会、市场估值或职业发展）：反映机会、俱乐部与时间等多重因素，不等同球员与一个特定职责的适配度。
- ** query-specific 球探适配判断**：评审者基于固定需求与证据，对冻结候选池逐人判断。这才与 TactiScout 的 nDCG 目标相符；当前未发现可直接拿来用的公开金标准。

## 建议

1. **不要导入未核验来源权利的 Scoutium/Kaggle 镜像作为金标准。** 可见页面或第三方 GitHub 副本不能证明原始数据许可、标注者资质与标签含义；即使标签真实，也需确认是否为具体招募职责适配，而不只是单场观察或潜力分类。
2. 继续使用项目已有的匿名盲评流程：冻结自然语言需求及其补充答案、固定候选池与来源快照；请至少两名评审者独立给出 0–3/`unknown`，再匿名裁决。原始分歧、缺项与候选池覆盖必须和 nDCG 一起报告。
3. 公开研究可用于**rubric 设计和局限说明**，不充当短名单正确答案。PlayeRank 可以作为通用比赛表现排序基线，前提是明确它不是 query-fit 基线且输入数据权利单独核验；不能拿其自身生成的分数当独立 ground truth。
4. 在积累多条真实 query 标签前，只发布案例级指标和覆盖情况，不宣称一般推荐准确率、职业球探共识或预测转会成功。

## 范围与限制

本审计检查了上述论文、作者项目及其关联的公开数据记录；结论是“本次检索未发现符合条件的基准”，不是证明世界上绝无私有或未索引的数据集。没有下载受限数据，也没有把非商业用途推断为授权。OSF 的 Rubrics 项目页本次无法读取文件级许可，因此报告只引用论文对可用性的陈述，不承诺数据复用权。
