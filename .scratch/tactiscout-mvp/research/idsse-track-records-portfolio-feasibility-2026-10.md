# IDSSE / DFL 追踪数据：作品集切片可行性

日期：2026-10-09；范围：评估是否把 2022/23 IDSSE 七场历史样本作为独立战术指标 benchmark；不下载比赛数据、不调用接口。

## 结论

**有界 GO：**可以做一个单场起步、可复现的离线战术 benchmark，但前提是人工确认官方档案可取得，并用本地文件核对比赛级切片与校验和。**当前数据导入暂缓；NO-GO：**不得将它接入现役候选池、默认球员评分或新增 `PlayerRepository`。AI / RAG / embeddings 没有专用授权文本，相关的 AI 专用许可状态保持**未知**；CC BY 对复制/改编的通用授权不等于明确的 AI 使用条款。发布页本次返回 403，档案清单、单场是否可独立下载、单文件大小和哈希均未核实。

该结论与项目既有历史样本边界一致：issue 40 要求每个统计证据保留赛事、赛季、来源、计算定义和缺失范围；issue 24 的 SkillCorner 数据是独立受控证据；issue 31 的 StatsBomb xG 不等于 tracking 证据。IDSSE 应作为单独的历史比赛切片，不与这些来源按姓名或字段名合并。

## 一手来源与数据形状

- [Scientific Data 论文](https://www.nature.com/articles/s41597-025-04505-y) 描述 2022/23 德甲两场、德乙五场；合计 207 名球员、10 支球队、11,137 个事件和 1,002,644 帧球员及足球坐标。作者明确说七场不足以得出可泛化的比赛分析结论，定位为入门分析与高质量基准；数据不含比赛视频。
- 每场有三类 XML：比赛信息、事件、位置数据。作者的[原始处理代码](https://raw.githubusercontent.com/spoho-datascience/idsse-data/main/data_processing.py) 调用 DFL XML reader 读取 teamsheet、event 和 position，并在表格中出现 `pID`、`team`、`eID`。代码通过排序后配对比赛信息与事件文件；在实际导入前应以比赛 ID 做关联校验，不能把排序配对当作可靠身份规则。原始 XML 的完整 XSD、每个字段定义及跨比赛 `pID` 稳定性没有在作者仓库中提供，须在真实文件 smoke 中核实。
- 作者的[官方仓库 README](https://github.com/spoho-datascience/idsse-data) 指向原始 Figshare 档案，并要求署名 DFL、引用论文。作者仓库提供读取/汇总脚本，不包含原始比赛行。
- [Springer Nature Figshare 发布页](https://springernature.figshare.com/articles/dataset/An_integrated_dataset_of_spatiotemporal_and_event_data_in_elite_soccer/28196177) 当前索引显示 2025-02-02 发布、CC BY、全档案 2.45 GB，并列有 “Download all”。本次打开官方页面遇到 403；这只说明本次研究工具不能读取，不证明普通浏览器也无法下载。可见目录没有给出单个 XML 文件名、各自大小或 SHA-256，也没有证明七场可分别下载；这些目前均为**未知**。因此“单场切片”暂定为获得档案后本机提取，不是已确认的单场下载入口；获取时应本机生成 SHA-256 清单。发布页与作者 README 均未描述 API key、订阅费或动态更新接口；这是静态 release，不应称为实时或持续更新源。
- **时间与身份：**论文说明位置由 TRACAB Gen5 多摄像头系统以 25 Hz 采集；作者 reader 有逐场 `pID` team-sheet 与事件 `eID`。因此它是球员 ID 索引的名单/轨迹样本，不是仅有匿名聚合指标的表格；但本次可访问的一手说明没有充分展示每个 ID 到姓名的映射字段，姓名是否对每行可读应在实际单场导入时核实。它也没有证明 `pID` 是可跨比赛/赛季使用的稳定全局 ID；跨比赛合并和与其他来源 identity bridge 均应保持关闭。队内 ID swaps 是论文明确记录的追踪风险。
- **事件与指标：**论文描述可见的事件类型包括传球、射门、犯规等，且七场有 171 次带 xG 属性的射门。位置序列可确定性派生距离、速度区间、加速度；全队位置可派生重心、队形伸展/紧凑度、空间控制等。论文推荐的 `floodlight` 工具列出强度、几何及空间控制计算方式，见[论文使用说明](https://www.nature.com/articles/s41597-025-04505-y)。这些应标为 TactiScout 派生量并保存公式、单位、样本窗口和追踪质量，不得直接解释成稳定“能力分数”。最近防守者距离可作为压迫上下文代理，不等于已观测到的压迫事件。
- **同步与误差：**事件和位置均带 ISO 8601 时间戳，但直接按原始时间戳对齐会有人工标注时差。作者用 DataBallPy 对 6,251 次传球/射门做同步，原始与修正事件时间差均值为 −0.37±1.82 秒，最大 27.34 秒；空间差的均值由 9.37±8.39 米变为 2.61±3.60 米，但最大值仍达到 75.35 米，而且无视频 ground truth 验证。论文还记录遮挡缺帧、投影误差、近距离 ID swap；高速位移/加速度指标应先做低通滤波。事件级空间解释必须携带同步方法与置信/质量门槛。

## 许可与用途边界

论文及[作者仓库](https://github.com/spoho-datascience/idsse-data)都说明 DFL 授权数据按 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/legalcode) 发布。该许可第 2 节明示可复制、分享原始材料并制作/分享改编材料，适用于各类媒介与格式；第 3 节要求署名、链接许可和材料来源、说明修改。它也明确不构成 DFL 背书，并且不授予隐私、公开权等人格权。

| 用途 | 一手条款支持情况 | 实施约束 |
|---|---|---|
| 本机保存原始档案 | CC BY 明确授予复制权；可用于本机研究切片。 | 保留来源、许可与原档案链接；原始档案放 Git 忽略的本地数据目录，另记哈希。不要把“可本机保存”误写成对其他 DFL 来源的授权。 |
| 本地指标计算与派生 | CC BY 明确允许制作改编材料；论文描述了该数据用于分析与 benchmark。 | 保存规则版本、原始 ID/行索引、修改说明；定位为历史描述，不生成现役候选或跨源综合分。 |
| 本地 Ollama / embeddings / RAG | **AI 专用许可未知。** CC BY 没有专门提到 LLM、embedding、训练或 RAG；它通用地授予复制/改编许可，也没有写明排除机器处理。不能把通用许可表述为明确的 AI 使用授权。 | 在不依赖 AI 专用授权的最小实现中，先做确定性本地指标与人工可读报告；若之后要将源行/派生文本写入模型上下文或向量库，先向作者/DFL 确认这一用途，或把 RAG 限定为已获许可的方法论文语料。任何模型生成结果不得改变原始数据事实。 |
| 派生报告或公开作品集 | CC BY 明确允许分享许可材料及改编材料；需按许可署名、链接来源与许可并标注修改。 | 报告写明“DFL 数据，Bassek 等，2025，CC BY 4.0；TactiScout 派生计算”，不得暗示 DFL 认可。公开展示球员姓名等仍要注意 CC BY 不覆盖的隐私/人格权；不提供原始全量档案的镜像。 |

这里的许可判断仅覆盖 DFL 对其有权授权的著作权/数据库权利；CC BY 本身也说明许可方只能授予其有权授予的权利。来源未对 AI 使用给出额外专门条款，因此应保留上述边界，不写成“LLM 训练/公开展示获得 DFL 单独背书”。

## 建议实现边界

1. **单场切片是条件项，不是当前可直接执行的数据下载。**人工先打开 Figshare 发布页验证档案能否取得；若能取到 2.45 GB 档案，再核对是否可提取单场的三类 XML、单文件大小/格式/许可，并保存原档案和单场切片的 SHA-256。若发布页仍不可得或只能依赖未核实镜像，数据导入 NO-GO，先只做合成 XML fixture。
2. 单独建 IDSSE 静态样本解析与指标模块，输出版本化数据质量摘要；一个比赛足以验证 XML 解析、`pID`/`eID` 对应、时间戳、缺帧和字段覆盖。通过后再考虑扩至其余六场。此模块不调用候选检索，不进默认球员评分。
3. 首批指标限制为易复现的**单场跑动负荷摘要、球队重心/形状摘要、经同步检查的传球/射门邻域几何**。所有速度/加速度经滤波后计算；“压迫”“创造空间”等只作为明确公式的代理描述。每个输出包含来源身份、比赛/赛季、参与时间、分母、计算版本、同步和缺失质量标志。
4. **不需要 `PlayerRepository`。**现有仓库接口以候选球员和球员—赛季统计为核心；七场比赛 XML 是逐帧/逐事件数据，既不构成当前赛季候选池，也未证明存在跨场稳定球员主键。只有未来另建具备真实跨场身份映射、明确用途的当前球员表现源，才应讨论该接口。

**最终建议：**列为“值得实现的独立历史 benchmark”，以单场验证开始；不作为当前球探候选源、不影响球员推荐排序、不与 Wyscout/SkillCorner/StatsBomb 指标直接拼接。眼下最小下一步是人工核验官方 Figshare 文件是否能取到；随后按一场数据建立本地 fixture/质量摘要和 ID/同步校验，再决定是否扩到完整 2.45 GB 档案。
