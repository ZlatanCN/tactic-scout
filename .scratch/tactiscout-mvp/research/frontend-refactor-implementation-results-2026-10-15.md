# 前端工作台重构：实现结果与边界

日期：2026-10-15

## 已实现

- `App.tsx` 收敛为工作台布局；招募会话的输入、追问、提交、取消、断线恢复、保存快照和计划切换由 `useRecruitmentSession` 统一持有。
- 实际阶段轮询、连接状态、经过时间、开始和取消阶段由 `useRecruitmentProgress` 持有；呈现由 `RecruitmentProgressCard` 负责。进度不合成百分比或伪造事件。
- 对话、保存计划、报告分别作为工作台的呈现边界。候选报告逐人判断本轮重点指标：有直接证据者进入核查顺序和比较；只有背景记录者放在独立区域，不显示能力名次或比较勾选。
- 空名单文案区分“没有记录到已完成的候选查询”和“查询范围内没有形成名单”，避免把未知原因说成市场上不存在匹配球员。
- 接入 Tailwind v4 与 shadcn/Base UI 控件。球队搜索延迟到首次打开时加载，辅助页面使用懒加载；没有加入第二个 UI 框架。把语义颜色、字体和品牌别名集中到 `index.css`，清除旧全局表面样式的第二份 token 定义。Beautiful UI 目前仍作为单项模式参考，没有引入其组件运行时。

## 固定数据消融：逐球员证据门槛

输入冻结为同一名单：候选 A 有一项本轮重点数据；候选 B 没有任何本轮重点数据。

| 实验臂 | 结果 |
| --- | --- |
| 去除逐人门槛（旧报告级全局判断） | 因 A 有重点证据，A、B 都取得比较资格；B 是误放行。 |
| 启用逐人门槛 | A 获得第 1 个核查序号且可比较；B 没有序号、不能比较，并归入背景记录。 |

`tests/report-presentation-ablation.test.ts` 验证两臂差异、名单排序和空查询文案；三项检查全部通过。这证明当前展示规则不会因为同名单中别的球员有证据而给 B 错误的能力比较资格。它不证明候选质量提升，也不证明用户理解速度、信任或放弃率改善；这些需要有人参与的任务实验。

## 全站样式迁移补充复核

本节记录 2026-10-15 后续完成的 Tailwind + shadcn 全站样式收敛，覆盖工作台、报告、球队选择、球员观察、盲评、裁决和 Showcase。

- 已删除 `styles.css`、`workbench.css` 以及各 Showcase/录制展示 CSS 文件。`web/src` 目前只保留 `index.css`：集中语义颜色、字体、圆角、全局基础规则与 reduced-motion 回退；组件视觉由 Tailwind utility classes 表达。
- shadcn/Base UI 成为共用控件基础，包括 Button、Card、Badge、Tabs、Accordion、Dialog、Dropdown Menu、Combobox、Select、Input、Textarea、Field、Alert、Progress、Table、Tooltip 等；延迟加载球队搜索与盲评/裁决/Showcase 的行为保持原有边界。Beautiful UI 仅作为视觉模式参考，没有引入第二套 CSS 或组件运行时。
- 产品目前固定浅色。`dark:` 工具类改为只响应显式 `.dark` 根类，避免操作系统的暗色偏好给浅色页面注入不一致的表单底色。输入边界对比度为 3.07–3.31:1，正文/弱化文字为 4.67–5.03:1，主焦点环为 6.40–6.90:1，白字主按钮 hover 为 5.79:1。
- 修复 sticky header 下跳过链接的锚点位置；计划名称输入补上键盘焦点；所有半透明焦点环改为完整主题色。加入系统减少动态效果时缩短动效的全局回退。
- 最新 `pnpm --filter @tactiscout/web build` 通过，`git diff --check` 通过。Vite 仍提示主 JS chunk 为 606.07 kB（gzip 193.29 kB），是可后续单独评估的首屏性能项，不阻止当前样式迁移。
- 浏览器手工检查工作台、Showcase、盲评和裁决页面；核对工作台跳过链接能将标题定位在 sticky header 下方。键盘样例按钮和可搜索球队选择（输入 Bayern 并选中 Bayern Munich）也已检查。最新预览视口约 708 CSS px；更窄视口先前检查过，但未在本次颜色/焦点改动后重做 390px 检查。
