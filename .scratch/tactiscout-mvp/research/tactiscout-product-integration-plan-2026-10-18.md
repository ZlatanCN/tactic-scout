# TactiScout 产品化整合方案

这份方案把 LangGraph 开源项目的实际控制流映射到现有 TactiScout。目标是让用户从一句自然语言开始，得到一份可继续探索、证据边界清楚的球探短名单。它是产品整合路线，不代表所有提议都已实现或已验证。

## 产品成功条件

一次案件应能：

1. 正确理解任务类型、目标球队、参考球员和用户明确提出的限制。
2. 只在答案会改变候选范围或决策时追问，并在用户回答后从同一案件继续。
3. 根据已有证据和缺口选择下一项有价值的调查；有界循环后明确结束、继续或给出部分结果。
4. 将候选资格、直接证据、定性线索、来源失败和未知分别表达。
5. 让用户看懂为什么保留候选、主要取舍是什么，以及下一步能做什么。

系统质量需要拆成两类证据：Harness 证明控制流、失败恢复、身份/位置约束和证据合同；独立足球评审证明具体样本下的短名单判断质量。前者不能替代后者。

## 目标架构

沿用一个案件状态所有者和一张主图。节点职责复用现有模块，缺口用评测证明后再加：

```text
记录用户回合 → 理解招募 brief / 解析身份
                         ↓
               必要信息缺失？
                ├─ 是 → 结构化追问 / interrupt / 同案恢复
                └─ 否 → 选择下一项调查
                           ↓
                  执行获准工具或子图
                           ↓
               归一化证据与候选资格
                           ↓
                还有重要证据缺口？
                ├─ 可查且预算允许 → 有界循环
                ├─ 需要用户判断 → 追问并恢复
                └─ 否/预算耗尽 → Reviewer → 报告
```

案件状态应继续使用一套规范化事实：用户原意、已确认条件、参考实体解析状态、证据账本、候选短名单快照、当前调查范围、未解决缺口、工具结果类别和运行预算。优先复用现有字段，不平行维护一份“Agent 隐藏状态”。

LLM 负责自然语言理解、在允许动作中选择下一项调查、解释证据。代码负责身份唯一性、本人排除、位置资格、样本口径、来源范围、分页游标、循环上限和失败类型。结果分别标记为成功、有证据的空结果、部分成功、无数据、数据源失败、身份不明或预算耗尽。

## 从开源案例吸收什么

| 模式 | 采用方式 | 明确边界 |
|---|---|---|
| Local Deep Researcher 的检索—反思 | 以当前证据缺口驱动下一轮搜索，累积结构化证据并限制循环 | 不让模型无限反思；空搜索不伪装成调查充分 |
| Open Deep Research 的并行子图 | 仅在两个数据任务互相独立且可分别失败时并行，最后按统一契约合并 | 当前先不创建通用 supervisor；先测并行对候选覆盖和等待时间的净收益 |
| DeerFlow / Deep Agents 的 harness | 延续每案隔离、预算、checkpoint、中断、取消、上下文控制和可观测性 | 不搬入代码沙箱、通用任务清单或大量跨业务 middleware |
| SurfSense 的窄工具面 | Planner 只看到语义清楚的能力工具；数据源与 provider 细节留在 repository/adapter 内 | 不为每个数据源再包一个 LLM Agent |
| Chat LangChain 的守卫与恢复 | 对模型输出、越权动作、超时与失败结果使用明确校验和恢复语义 | 重试必须有次数上限，并保留失败原因 |
| OpenGPTs 的不同认知路径 | 明确查询走确定步骤；需补充调查的案件走动态工具循环 | 不把每个请求都送进长 Planner 循环 |

## 执行顺序与验收门

### 1. 关闭真实模型可靠性缺口

使用 issue 211 的原始输入重跑需求解析和完整链路。已确认模型版本、输出上限、终态、候选/Planner 调用；adapter 未暴露原始 `finish_reason`，所以此字段仍未直接观测。真实运行已进入预期位置追问，无长度错误。

### 2. 冻结代表用户真实意图的整图场景

用现有 Harness 能力构成版本化场景集，重点覆盖：

- 替代者、接班人和本人排除；
- 跨语言球员名、别名、错字和身份歧义；
- “类似某球员”的能力解释；
- 宽泛位置与细分职责、明确位置与未定位置；
- 用户中途改需求、放宽限制和继续比较已有短名单；
- 来源超时、部分数据、成功但无结果及证据不足。

Harness 指标至少报告：身份/意图正确性、候选资格错误、请求能力证据覆盖、无依据断言、追问次数与必要性、调查动作、工具错误语义、停止原因、耗时和 token。按冻结输入做配对消融；同一个机制不得只看单节点成功率。

### 3. 补上短名单质量证据

先完成 [issue 168](../issues/168-collect-independent-one-on-one-review-labels.md) 的双人盲评和匿名裁决，严格保持其历史、单角色样本范围。然后为替代者、相似球员和位置补强各选固定样本，逐步建立有足球判断标签的 query-specific 评测集。没有标签的范围继续标成 `not_evaluable`，不从工具命中率或推荐数量推断质量。

### 4. 用证据驱动完善问答和报告

把用户能参与的决定点做成结构化输入，例如位置选择使用可多选的球场；其余能力偏好仍用自然语言。报告默认提供短名单理由、关键指标、风险和未知，来源口径与全量指标按需展开。报告完成后，用户可以继续比较本轮候选或修改一项条件；短名单快照必须随案件状态延续。

### 5. 只在配对实验支持时增加并行研究

选一组真实且相互独立的数据查询，比较串行与并行：相同候选资格、证据引用和失败分类下，测量端到端等待、超时率、资源开销和部分失败处理。如果并行只增加复杂度或改变报告证据，就不进生产图。

## 核心消融矩阵

优先复用已有的公开评测接口，不重复制造 CLI：

| 机制 | 对照 | 能回答的问题 |
|---|---|---|
| 动态调查 Planner | 固定调查计划 | Planner 是否找到了固定计划漏掉的有效证据，代价多少？ |
| 必要追问与同案恢复 | 安全暂停/禁止追问 | 追问是否解决实质歧义，是否避免无效回合？ |
| 确定性候选/证据门 | 模型单独判断 | 是否减少本人混入、位置错配和无证据推荐？ |
| Reviewer | 关闭 Reviewer | Reviewer 是否捕捉并修复具体证据/报告缺陷？ |
| 定性 Web Search | 无 Web Search | 是否增加可核验观察，同时不冒充统计证据？ |
| 并行独立调查 | 串行调查 | 是否降低等待且保持结果合同和可解释失败？ |

已有结果按适用范围复用：issue 203、207、211、217 已覆盖其中若干机制；新增实验必须指出现有证据的具体盲区。

## 完成标准

- 主图对六类关键结果（成功、有证据的空结果、部分结果、无数据、工具失败、需要用户输入）有明确状态和 UI 呈现。
- 固定场景的整图行为可复跑、结果可追踪；消融只支持实验实际证明的结论。
- 真实短名单质量仅在有独立足球评审标签的样本范围内报告。
- 模块和图节点维持单一职责；增加子图、并行或新 middleware 前须有产品痛点、公开测试 seam 和配对实验。
- 工作台真实非空报告、追问恢复、继续比较、失败重试和窄屏视图完成验收。
