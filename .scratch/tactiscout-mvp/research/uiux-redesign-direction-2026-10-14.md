# TactiScout 全面 UI/UX 改版方向

日期：2026-10-14。依据：[官方竞品研究](uiux-market-patterns-2026-10-14.md)、本机当前首页/已保存案件的浏览器观察，以及 App.tsx、RecruitmentReportPanel.tsx 等现有功能。本文件是设计方案，不是已实现功能或效果验证。

## 产品判断

围绕一次招募任务组织界面：提出问题→确认关键条件→阅读候选→对比依据→保存计划→继续调查。首页、运行中与结果状态应有不同主次关系。自然语言保持主要入口，结果保留独立阅读空间。

Wyscout 官方截图及流程表现出搜索结果、固定球员身份、选择/加入名单的结构；Statsbomb 官方图展示左侧控制、右侧可扫描的指标表。TransferRoom 官方文档把短名单动作放在球员旁。借鉴工作组织方式，不复制完整专业数据库的字段和交易功能。出处见竞品研究。

## 当前页面的具体问题

1. 在当前约 910px 窗口，横幅和整块计划区域占据首屏上半部，输入框接近屏幕底部；输入未发生时仍有完整空报告，占用第二块大型区域。
2. 导航同时放研究、观察、盲评和质量评估；新用户开始找球员之前要面对研究工具的分类。
3. 案件标题是可选名称输入，状态和本次需求未形成稳定的任务标题；计划、案件与最近报告的关系需要从文字中推断。
4. 已保存案件有多轮旧追问、已停止消息和旧报告；目前报告仍呈现完成标记，版本关系和恢复方式不够醒目。
5. 无候选报告先展示大块能力覆盖再展示零人结果；原因和下一步较晚出现。正常候选卡已有折叠基础，可继续减少重复说明。
6. 当前页面同时使用大段说明、英文小标题、浅色边框和装饰图形。建议把视觉强调集中于任务、候选身份和主要操作。

这些是观察与设计判断，没有做用户实验，不能把它们当作已验证的转化问题。

## 全面改造清单

| 层次 | 新组织方式 | 现有能力与边界 |
| --- | --- | --- |
| 全局导航 | 案件/保存计划是主入口；评测、盲评、运行展示收进次级工具区 | 保留现有页面，不删评测能力 |
| 初始页面 | 输入在视觉中心；三个简短任务示例；近期计划紧凑呈现 | 不新增引援表单；来源简短显示，限制可展开 |
| 活跃案件 | 紧凑任务标题、状态、最近报告时间；宽成果区、可收起的对话区 | 对话控制仍复用现有 turn 接口，不引入新的 Agent 流程 |
| 等待 | 当前实际步骤、少量已完成事实、耗时和停止；完整步骤折叠 | 不显示假进度百分比；不把未评估球员当最终候选 |
| 追问 | 问题是当前主操作；原因按需展开；输入保留自由回答 | 当前接口没有结构化建议答案，不从问题文本猜按钮值 |
| 正常结果 | 一段结论→候选→比较/证据→限制与下一步 | 不增加未验证综合分；指标沿用实际返回的值和定义 |
| 空结果/失败 | 先说原因与可执行下一步；区分来源缺数据、请求失败、条件无匹配 | 缺年龄不等于符合；零匹配不等于请求失败 |
| 候选卡 | 身份、比赛样本、3–5项相关指标、主要风险；比较操作就近 | 比较复用现有选择状态；单独收藏球员属于新增功能，另行评估 |
| 比较 | 默认2–3人；固定姓名和指标标签；相关维度优先，单位/赛事/分钟始终可查 | 不跨源拼统一百分位；未知显示“未提供”，不按零绘图 |
| 来源与完整报告 | 独立“依据”层；保留可核查链接和口径，不在每张卡重复全部说明 | 关键小样本和缺失能力仍在首层可见 |
| 保存/恢复 | 计划列表可重开；清晰显示保存报告与当前调查；删除动作次级化 | 不暗示 localStorage 等于服务端 checkpoint；旧快照不能默认为最新结果 |
| 小屏 | 对话、候选、比较切换视图；输入容易触达；仅比较表受控横滚 | 不能直接把桌面多栏缩小塞进手机；保持键盘和读屏可用 |

## 建议的页面结构

### 未开始

紧凑应用导航 + 近期计划入口；主要区域为“一句话开始招募”的输入与三类示例（替代球员 / 补强位置 / 寻找能力）。空报告区域不常驻。

### 调查与追问

任务标题和状态在顶端。主体保留对话与成果区：成果更宽，对话可以收起；窄屏用视图切换。调查中显示真实进展，追问时聚焦问题，更新已有报告时明确标出“上次报告”，不会悄悄覆盖。

### 报告完成

成果默认视图：结论、候选、就近比较动作；完整依据另层。对话仍可继续修改需求。保存计划和查看最近报告保持可达，不占据正文大块空间。

## 视觉方向

- 采用中性浅底、清楚的深色文字、单一绿色强调；保留足球产品辨识度。
- 控制卡片和分隔层级，不使用卡片套卡片。减少英文装饰标签、大片空白和没有数据含义的装饰雷达。
- 正文/数字/说明形成稳定层级；数值对齐，单位相邻；信息密度随任务变化。
- 状态不只依赖颜色；风险使用文字和图形提示，未知不染成低分。
- 桌面考虑空间充足的成果区；手机从输入、追问和候选阅读出发设计，不只是加一个断点。

## 实施顺序

全部纳入改版范围，但按依赖推进：

1. 工作台骨架和页面状态：首页→调查→追问→成果，以及导航/小屏结构。
2. 候选、比较、证据与保存恢复的一体化交互。
3. 统一视觉规则、控件、键盘焦点、错误/空态和响应式细节。

开始实现前用可交互页面检查这些状态。设计样本必须明确是样例，不能用真实姓名配编造能力分数；不需要启动慢模型来判断布局。正式落地仍使用现有真实数据与运行状态。

## 验收问题

首次进入能否直接找到输入？追问能否清楚回答？等待时能否知道实际状态并停止？报告是否先说结果和理由？比较两人是否无需穿过长文？来源、口径和未知能否找到？保存后能否分清旧快照与新调查？小屏是否无整页横向溢出？仅键盘能否完成主要流程？

## 调研访问限制

SciSports 官方图片的浏览器访问被自动审批超时阻止，并非判定页面不安全；未绕过。有关其当前界面的观察仍限于官方文字说明。竞品图只用来分析结构，不宣称已实测登录后的最新产品。具体出处与证据强度见竞品研究。
