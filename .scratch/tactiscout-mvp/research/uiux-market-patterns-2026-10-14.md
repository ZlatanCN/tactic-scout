# TactiScout UI/UX 竞品研究

调研日期：2026-10-14。范围：官方公开产品页、支持文档、公开产品截图；没有登录付费平台，没有验证登录后最新交互。以下“建议”是结合 TactiScout 的设计推论，并非竞品的效果实验。

## 结论

专业球探产品围绕可持续维护的候选名单组织工作，对话研究产品围绕需求、过程和可核查报告组织工作。TactiScout 适合结合两者：自然语言开启研究，确认必要条件，产生候选名单，再进行少量候选比较与证据复核。对话是控制入口，候选与报告是工作成果。

不建议照搬专业工具的海量筛选器或几十列指标，也不建议把完整报告塞进聊天气泡。主视图应当优先回答：正在考察什么、哪些候选值得继续看、各自依据与缺口是什么。

## 1. Wyscout：搜索结果与名单是两种工作状态

官方示例截图可见：左侧联赛/时间/位置与指标范围；右侧可选择球员的表格，上方 All results / My pins、Add to list、Display，下方分页与导出。球员身份、球队、位置、年龄、出场分钟和表现指标同一行。来源：[官方截图](https://static.hudl.com/craft/blog/Belgian-Advanced-Search.png)。

官方文章描述需求定义→长名单→深入视频/数据分析→短名单→决策呈现，强调先缩小名单再加深分析。来源：[Discovery to Deal](https://www.hudl.com/blog/discovery-to-deal-building-shortlist-wyscout)。

**借鉴**：候选与已收藏名单应明显区分；卡片保留身份与样本信息，名单可复用。**不照搬**：满屏国籍、合同和市场字段；当前来源缺这些信息时不展示假筛选器。

## 2. Hudl Statsbomb：结论必须能够回到证据

实际截图显示紧凑的左筛选/右指标表布局，位置选择与年龄、身高、分钟范围在侧边栏；彩色单元格服务于横向扫描。来源：[官方截图](https://static.hudl.com/craft/statsbomb-platform-narrow-your-search-with-precision-2.webp)、[平台页](https://www.hudl.com/en_gb/products/statsbomb/platform)。

2026 更新说明包括：名称列固定、百分位/原值切换、无数据留空、搜索结果预览，以及文字发现可追溯到事件和视频。来源：[官方更新日志](https://www.hudl.com/releases/statsbomb)。

**借鉴**：比较表固定姓名；每个指标说明口径、样本、时间和来源；未知不能染成低分；短摘要紧邻可展开依据。**不照搬**：没有事件/视频证据时不画热图、战术路线或完整能力雷达；不能把不同来源的百分位直接拼起来。

## 3. TransferRoom：收藏动作就在球员旁边

实际查看的支持截图在球员姓名旁放 Shortlist、Notes；基本身份一行呈现，价格/可用性另成视觉区。官方步骤允许从搜索或球员资料加入已有名单或新建名单，并从名单视图返回。来源：[短名单支持文档及截图](https://knowledge.transferroom.com/how-to-use-shortlists)。

当前 Scout 产品页描述 AI 汇总报告、比较球员和短名单推荐；这是官方能力说明，未核实内部布局。来源：[TransferRoom Scout](https://www.transferroom.com/transferroom-scout)。

**借鉴**：收藏与比较都应靠近候选，动作后立即反馈；保存计划应保存当前成果并便于重开。**不照搬**：报价、联系俱乐部、可买/可租等交易动作，TactiScout 没有这些实时数据和关系网络。

## 4. SciSports：少量球员比较比海量卡片更易决策

官方 2021 功能文章描述最多三人并排比较基本信息、发展、职业统计和风格；表现筛选先生成小范围候选。当前 Scouting 页面仍强调搜索、筛选、比较与短名单。来源：[功能说明](https://www.scisports.com/scisports-releases-new-features-to-bring-innovative-data-insights-into-football-recruitment/)、[当前 Scouting 产品页](https://www.scisports.com/scouting/)。

**借鉴**：比较选择数量有限，比较页集中展示这次任务最重要的指标。**不照搬**：潜力与职业发展预测；没有纵向或验证模型就不能呈现潜力分数。上述比较布局仅由官方文字确认，未看见实际图像。

## 5. Comparisonator：替代某球员是清晰的入口

官方 Similarity Comparison 描述以参考球员寻找相近风格，并用相似度、年龄、分钟等细化；Recruitment Shop 按通用、进攻、防守、传球等组组织大量指标。来源：[Similarity Comparison](https://comparisonator.com/products/similarity-comparison)、[Recruitment Shop](https://comparisonator.com/products/recruitment-shop/)。

**借鉴**：首页示例分成“替代某球员 / 补强某位置 / 寻找某能力”；需求和比较按足球能力分组。**不照搬**：专有跨联赛指数、相似百分比与虚拟转会预测。当前算法与数据不支持就不能装成已验证能力。这里仅核实产品说明，没有看到可辨认实际截图。

## 6. 对话式研究：对话与成果有独立阅读方式

ChatGPT 官方文档描述先提出研究目标，可澄清需求和修改计划；运行中看进展、调整范围；完成报告有目录、来源和活动历史，并可下载。来源：[Deep research 帮助文档](https://help.openai.com/en/articles/10500283-deep-research-in-chatgpt)。

**借鉴**：运行状态呈现已确认需求、当前任务与已取得事实；追问只围绕会改变下一步的决策；报告有专门阅读区域，活动记录按需展开。**不照搬**：未经复核就展示最终候选，伪造完成百分比，暴露原始模型推理。

Perplexity 官方搜索结果指出 Deep Research 后改名 Research，介于 Search 与 Labs；正文无法可靠打开，不能据此声称它如何中断/追问。来源：[官方 Labs 发布页](https://www.perplexity.ai/en-GB/hub/blog/introducing-perplexity-labs)、[官方博客索引](https://hub-prod.perplexity.ai/)。

## 给 TactiScout 的完整改造建议（设计推论）

| 区域 | 建议 |
| --- | --- |
| 全局导航 | 招募工作台与保存计划为主要入口；评测/盲评/Showcase 等研究功能放次级工具入口，保留能力但不占主任务空间 |
| 首次进入 | 一句自然语言输入与三个足球任务示例；不要求先填表；来源状态低调可查 |
| 调查工作台 | 对话作为需求控制区；成果区更宽；当前案件标题、需求摘要与状态始终可辨认 |
| 等待 | 展示真实当前步骤、已完成事实、耗时和停止动作；技术活动日志折叠；不能用虚假阶段制造进展 |
| 追问 | 问题、为什么需要、少量建议答案；允许自由回答；缺字段的原因明确，不把数据缺失说成市场无人 |
| 候选 | 默认身份/样本、推荐依据、主要风险、三至五个任务指标；来源细节展开；保存与比较就近 |
| 球员比较 | 二至三人、固定姓名、同口径指标、未知留空；可按能力分组；不自动假设所有颜色都是可比百分位 |
| 报告 | 简短结论→候选→权衡→下一步；完整依据另层；旧报告更新中有明显版本状态 |
| 计划 | 清楚区分已有快照与重新调查；恢复后仍能看原需求与结果；删除需确认 |
| 视觉 | 中性色主背景、单一强调色、清楚层级、足够正文字号；数字对齐；风险靠文字和形状而不只靠颜色 |
| 小屏 | 对话/候选/比较按视图切换，输入保持易到达；表格受控横滚；不硬塞三栏 |

## 交付与验证边界

这份研究证明的是竞品公开呈现了哪些机制，没有证明借鉴这些机制必然提高转化或推荐质量。下一步应以当前后端真实数据与已有功能构建完整可交互设计，检查首次输入、等待、追问、报告、比较、保存、失败与手机布局。优先整理信息架构与状态，再统一视觉；不要为贴近竞品补大量没有数据支撑的新业务功能。
