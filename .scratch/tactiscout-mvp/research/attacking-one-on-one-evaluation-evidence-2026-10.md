# Wyscout 进攻地面对抗：指标口径、来源与评审样本适用性

**核验日期：2026-10-10**  
**结论：有条件适合做历史、按具体需求盲评的短名单样本；不适合作为当下转会市场或现役名单数据。**

## 判断摘要

1. Wyscout 旧版事件表把 `eventId=1` / `eventName=Duel`、`subEventId=11` / `subEventName=Ground attacking duel` 定义为地面进攻对抗。它指控球球员参与的地面对抗，不等同于每次一对一过人尝试。
2. `701=lost`、`702=neutral`、`703=won` 是对抗的**简化结果标签**。Wyscout 另有独立的 `Successful: Yes/No` 口径；两者不能混为一谈。按 `703 / (701+702+703)` 算出的应称为项目派生的“明确胜出占比”，不能称作官方进攻对抗成功率，更不能叫“过人成功率”。
3. 公开数据不是 TactiScout 或研究者从比赛视频独立采集的数据：数据论文记载其由 Wyscout 收集并提供，采用专家视频标注员、专有标注软件和自动/人工质检；研究者通过 Figshare 发布数据集。论文说明这些数据集按 CC BY 4.0 发布。
4. 它能支持**冻结在历史时间点**的表现证据评审，例如评审者根据 2017/18 赛季事件数据判断球员对某个明确角色要求提供了多少支持。它没有提供现时注册名单、合同、身价、预算或可签约状态，不能支撑 2026 年的现役引援候选池或转会可行性判断。

## 事件和标签的准确含义

Wyscout 官方旧版 API 支持文档将 `1 / 11` 列为 `Duel – Ground attacking duel`，并列出 `701 lost`、`702 neutral`、`703 won` 标签。[事件/子事件与标签表](https://support.wyscout.com/matches-wyid-events)（官方文档；本次核验访问：2026-10-10）

Wyscout 官方术语表进一步限定了语义：进攻对抗是**持球球员参加的地面对抗**；试图用技术动作越过对手时，该事件也属于 Dribble，但用身体护球的进攻对抗不属于 Dribble。此类事件可发生在球场任何位置，包括球员自己的禁区，并且会与对手的一条防守对抗事件配对。[Offensive Duel 术语表](https://dataglossary.wyscout.com/offensive_duel/)（官方术语表；本次核验访问：2026-10-10）

该术语表把两种结果口径分开：

- **`Successful: Yes/No`**：根据后续动作是否向对方球门推进、特定盘带后队友是否向前触球，或防守方是否犯规等规则判定；不符合列出的成功条件即按该口径计作失败。
- **`Outcome: Clearly won/lost/neutral`**：`703/701/702` 对应明确胜出、明确失利、中性。这个“较不复杂”的算法看下一动作是否由对抗双方之一完成；若是，该球员明确胜出、对手明确失利；其他情况标中性。

因此，若 TactiScout 汇总标签 703 的事件，并以 701、702、703 的总数为分母，准确名称应是：

> **Wyscout 进攻地面明确胜出占比（项目派生）** = 703 / (701 + 702 + 703)

中性事件留在分母，意味着它刻画的是被标为“明确胜出”的事件占已分类事件的比例；它不是 Wyscout 官方另列的 `Offensive Duels %`（官方术语表将其描述为成功进攻对抗的比例）。若 TactiScout 当前代码使用上述标签公式，UI 和报告应始终使用“明确胜出占比”并给出公式/定义，不应误标为官方成功率。

### 这两个派生统计能说明什么

- **进攻地面对抗次数（或每 90 分钟）**：该数据源中记录了多少次该类事件；可作为球员参与持球地面对抗频率的线索。
- **明确胜出占比**：在该事件分类体系中，有多少已分类事件得到 `won` 标签；可作为对抗结果的粗略比较线索。

### 不能据此声称什么

- 不能直接称为过人/盘带尝试次数或成功率：不少进攻对抗是护球；进攻对抗也可能发生在己方禁区或其他不对应突破的区域。即使某些 dribble 同时被记作进攻对抗，整个进攻对抗集合也不等于 dribble 集合。
- 不能单独证明推进能力、摆脱压迫、创造威胁、边路一对一能力或某个战术职责的整体适配；该标签没有说明对抗情境、压迫强度、动作价值或后续进攻收益。事件坐标可以提供位置线索，但需要明确再做区域限定，且不能替代视频判断。
- 不能把中性结果当成成功，也不能把这组标签公式与 Wyscout 的独立 `Successful` 规则当成同一口径。
- 不能仅凭总次数或比例忽略分钟、赛事、位置、球队战术、对手与样本量；跨赛事/位置直接排名仍需额外可比性控制。

## 数据集的来源、时间范围和许可

Pappalardo 等人在 *Scientific Data* 的数据描述论文称，数据由 Wyscout 收集并提供；采集由受训的专家视频分析员用专有 tagger 完成。每场由三名操作员标注（两队各一名，另有监督员）；质检包含自动检查和对抽样比赛进行的人工复核。论文同时明确写明，Figshare 上发布的**数据集**按 CC BY 4.0 许可提供。[论文（2019-10-28 发表）](https://www.nature.com/articles/s41597-019-0247-7)；[Figshare 数据集集合](https://figshare.com/collections/Soccer_match_event_dataset/4415000/5)（集合版本 5 发布于 2020-01-28；该集合说明数据收集方为 Wyscout，署名作者为 Luca Pappalardo 与 Emanuele Massucco）。

论文所述俱乐部联赛样本是**2017/18 赛季**的西甲、意甲、英超、德甲、法甲，另有 2018 世界杯和 2016 欧洲杯国家队赛事；总计约 1,941 场、3,251,294 条事件、4,299 名球员。字段 `currentTeamId` 是论文数据记录中的球员球队字段，时间语境仍属于该历史数据集，不能解释成今天的现役归属。来源和范围以论文 Data Records 为准。[论文 Data Records](https://www.nature.com/articles/s41597-019-0247-7#Sec6)

CC BY 4.0 的使用条件包括适当署名、附许可链接，并说明是否做过修改。[Creative Commons Attribution 4.0 International](https://creativecommons.org/licenses/by/4.0/)（许可文本；本次核验访问：2026-10-10）。项目应在数据/评审材料中记录原作者、论文、Figshare 集合、赛季范围、许可和派生修改。这个结论针对该论文/Figshare 发布的具体公开数据，不应外推为可抓取、再发布或处理 Wyscout 其他产品、API 或视频内容的授权。

## 是否适合作为真实人工短名单评审样本

**适用：历史、角色限定、证据可追溯的人工评审。** 可冻结某个历史赛季和候选池，给评审者一个明确且与该时间点相容的招募需求，匿名呈现候选证据（包括此类对抗统计及其口径、赛事/赛季、分钟、位置和缺口），让评审者独立判断“该候选是否值得按这个角色继续考察”。这是真实比赛数据上的 query-specific 适配判断，适合验证匿名盲评工作台、证据解释和评审分歧流程。

**不适用：当前市场的真实引援结论或当前名单质量基准。** 赛事样本年代久远且范围有限；论文/Figshare 数据集并未给出可用于现时引援判断的当前注册状态、合同、身价、预算、可签约状态或完整全球候选覆盖。需要当前市场的 benchmark 时，该数据集只能作为明确标记的历史表现证据，不能冒充候选发现来源或当前球员池。

**它也没有现成的短名单“标准答案”。** 事件数据提供表现事实/分类，不提供对某个招募需求的专业适配真值。若要检验排序，应为固定 query 和冻结候选池另行取得独立人工评分、处理 `unknown` 并保留裁决流程；Wyscout 的事件标签不是球探共识标签。对抗次数/明确胜出占比也只能作为有限证据之一，不能机械映射成 0–3 适配等级。
