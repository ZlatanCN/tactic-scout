# 208 — 替代者请求继承参考球员位置，不再默认追问

Type: bug
Status: resolved
Labels: ready-for-agent

## Objective

用户说“为某队寻找某球员的替代者/接班人”时，默认按参考球员的典型位置与主要角色寻找接班人。不能反复询问“延续原角色还是换位置”。

## Diagnosis

- 流程曾把“本地阵容/统计数据里没找到参考球员”错误地等同于“无法判断他的场上位置”。
- Harness 把任何没有结构化解析出位置的替代请求都强制改成位置追问，即使 Planner 已根据稳定足球知识提出了具体位置搜索。
- Planner 也曾把泛问“是否延续角色”写成默认追问；这既多余，也没有真正利用足球语境。

## Change

- Planner 明确将替代者理解为同位置/主要角色的接班人。找不到本地资料时，对位置明确的知名球员使用稳定的位置知识，直接提交有具体位置的候选搜索。
- Harness 接受 Planner 给出的具体位置搜索，并把该位置作为 agent-interpreted 搜索范围记录。仍无可靠位置时，只允许询问具体缺失的身份或位置。
- 通用的“延续参考球员角色还是换位置”问句会被策略拦截；LangGraph 只在球队资料检查后允许针对缺失位置的具体追问。
- 用户自己明确指定位置时，仍按用户范围搜索；同位置确实没有结果时，沿用现有的扩围确认流程。

## Verification

- `tests/recruitment-conversation.test.ts`: 53/53 通过，覆盖门将、中锋和前腰等多种位置；含“本地没有参考球员记录，但 Planner 能解析稳定位置”的整图场景，以及通用同/不同位置问题被拦截的回归。
- `pnpm build` 通过。
- `candidate-search-intent`、参考球员身份与位置解析、Planner 指令的定向测试通过。

测试使用固定 Planner 验证 LangGraph 的真实状态流转与 Harness 策略，不等同于本机 Ollama 实际模型的在线体验验收。
