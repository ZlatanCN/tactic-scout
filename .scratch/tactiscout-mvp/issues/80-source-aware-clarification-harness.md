# Make multi-turn clarification checks depend on observed source results

Type: task
Status: resolved
Labels: ready-for-agent
Blocked by: none

## Goal

让同一份真实 LangGraph Harness 场景能适配不同数据仓库：有符合确认位置的候选时，允许续用该位置已验证的分页游标并完成报告；只有工具实际确认该位置无匹配时，才要求询问用户是否扩大位置范围。

## Why now

2026-10-06 的 ASA 当前赛季真实运行中，工具先在首轮以 `ST` 搜索第一页，读出 315 条匹配，再向用户确认职责。用户确认中锋后，Agent 沿同一仓库分页继续调查并生成报告。Harness 错把历史 Wyscout 场景中“中锋无匹配”的路径强加到所有来源，误报缺少新的 offset 0 和缺少扩位调查。

## Scope

- 在 Harness 的公开评估函数上覆盖有匹配与无匹配两条数据驱动分支。
- 将确认位置分页校验与同案可复用的首轮分页历史对齐。
- 保持空结果时必须先获得用户扩围同意，再按来源返回的下一位置范围搜索。
- 不修改 LangGraph 决策，不以 fixture 代替真实来源或模型验收。

## Acceptance criteria

- 已发现确认位置候选时，Harness 接受从首轮 offset 0 延续到补答后的下一个有效游标；Agent 可直接按确认位置完成报告。
- 已确认位置返回零匹配时，Harness 仍要求后续的扩大位置搜索在该空结果之后开始，并且仅在用户补答后执行。
- 错误/跳跃分页不因跨轮续跑而通过。
- 确定性 Harness 测试和选定的数据仓库到 LangGraph 报告验收均通过。
- 报告质量边界继续区分流程通过与推荐排序准确性。

## Answer

Harness 的拜仁追问场景现在根据仓库实际结果分支：来源有确认位置候选时允许同案沿已有游标续查并在该位置完成；来源确认无匹配时，只有在空结果后向用户发出等待输入事件、收到下一轮补答后，才允许按更宽位置搜索。分页、进度与最终候选位置继续校验。

修复经 35 项定向 Harness 测试、全套 229 项测试、API/Web 生产构建以及一次真实 ASA/Qwen 多轮链路验证。ASA 本次运行通过全部 20 项检查，耗时 201.3 秒，评估 30 名候选并返回 1 条有来源证据的跟进线索。它验证完整数据到报告的执行行为，不证明候选排序准确性；球员报告语料本次 0 命中。
