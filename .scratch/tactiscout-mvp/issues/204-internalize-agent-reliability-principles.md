# 204 — 将 Agent 实践内化为球探产品的可靠性机制

Type: task
Status: resolved
Labels: ready-for-agent

## Objective

从“给用户可核对的引援考察建议”出发，将固定案例、证据状态、暂停恢复、无进展保护和可观测性落实到现有项目。对当前实现作对抗性检查，以整图消融判断新增机制的必要性；保持现有模块职责，不另建通用 Agent 框架。

## Acceptance and evidence

- 固定案例：`pnpm test:recruitment-core` 复用七个现有/新增测试文件，固定覆盖替代者排除、空名单、条件更新、同案追问恢复、取消、证据缺失、Reviewer 与按需检索对照。专项案例并入相关文件，全量测试继续包含它们。
- 证据状态：`conversation/state.ts` 的发现记录、独立评估、检索资料和来源观察贯穿工具投影、Reviewer 与报告。`recruitment-evidence-evaluator-ablation.test.ts` 对照有证据/屏蔽证据；`recruitment-comparison.test.ts` 验证显式零、缺失和不可比范围。这些机制已存在，继续使用。
- 持久化暂停/恢复：`wait_for_user` 使用 LangGraph interrupt，运行时从同一 checkpoint resume；核心测试覆盖追问、恢复、条件变化和取消。复用记录在正常新回合及 interrupt 答复后都清空。
- 无进展与重试：已有候选游标、重复评估、报告检索与独立工具预算保护。补足方法资料成功查询复用；修复原有“只按动作类型比较”导致不同请求误停的问题。
- 消融：`methodology-reuse-ablation.test.ts` 通过公开 `createRecruitmentConversation` 运行同一完整图，唯一变项为方法查询复用开关；同一脚本分别在零命中和有来源资料情况下执行。
- 高内聚、低耦合：复用逻辑集中在工具节点，一项轮次状态记录成功请求摘要，沿用 turn 初始化；不增加节点、外部缓存、动态 token 调度器或新评测平台。

## Adversarial findings and decisions

1. 重复成功方法查询仍会访问索引，而证据已在当前状态和历史中。仅复用精确 query + limit 的成功结果，包含零命中；失败不进入复用记录。查询不同、数量不同或用户进入下一轮都实际重新查。
2. 候选和球队数据会变，评估还会读取比较组。不能因为工具名字和输入看似相同就一律缓存；这些读取继续服从原有分页、最新需求与评估策略。
3. 原有 `sameBlockedAction` 只比较 action 名字，会误把不同查询当作同一次无进展尝试。现在比较经 schema 解析后的完整动作以及上一条拒绝说明；已有安全步数和工具预算仍限制不同动作持续失败的情况。
4. 使用专门 `tool_reuse` trace 记录复用事实，避免把未执行的索引访问伪装成一次实际工具调用。公开摘要不含查询、球员名或返回正文。
5. 重复尝试仍消耗现有尝试预算；复用既不扩充预算，也不让错误继续无限循环。

## Ablation results

| 固定整图场景 | 复用开启 | 复用屏蔽 | 保持不变 |
| --- | --- | --- | --- |
| 相同成功查询、零命中 | 索引访问 1 次 | 索引访问 2 次 | 完整报告相等，后续真实候选搜索均执行 |
| 相同成功查询、有来源资料 | 保留 1 个片段和来源 | 保留 1 个片段和来源 | 完整报告相等，来源 URL 保留 |

对抗性回归另验证失败可原样重试、不同 query/limit 不复用、checkpoint 答复后重新查询、不同受拒动作可继续到候选发现。

这是一项确定性机制的受控整图实验，Planner 是固定脚本。它证明重复索引访问可以省去且没有丢失报告证据，不证明真实 LLM 的触发频率、端到端延迟、token 节省或推荐排序质量。

现有真实模型消融结果也已重新读取：issue 203 对应本机冻结 Understat 快照 `9398c6515cd10d8b96d23bf4120e6bad2751375b7e5eca3bfddedbee0e5d50e2`，12 次完成调查。确定性必需步骤旁路由 4 增至 7 次 Planner 调用、token 由 10,362 增至 16,633；Reviewer 屏蔽产生重复候选。保留它们的依据仍是行为与成本，不是排序质量或框架优越性。
