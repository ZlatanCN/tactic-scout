# 210 — 重构球探工作台前端

Type: task
Status: resolved
Labels: ready-for-agent

## Objective

让用户能快速描述招募需求、看懂调查进度、辨别哪些候选有直接证据，以及继续追问或比较候选。重构前端结构和视觉基础，保留现有 API、LangGraph 工作流、浏览器计划存储及盲评/Showcase 的行为。

## Acceptance

- [x] 报告按球员逐人标示证据状态；缺少本轮重点证据者不能得到能力排名或进入能力比较。
- [x] 调查进度明确呈现实际阶段与运行状态，等待、连接中断、取消与完成语义不混淆。
- [x] 新建需求、补充回答、查看报告、打开/保存计划在桌面与窄屏下保持清晰且可键盘使用。
- [x] React 页面按用户任务拆分，异步运行状态与纯呈现职责有明确边界；不引入重复的状态源。
- [x] Tailwind/shadcn 提供一套基础；Beautiful UI 只采用与本产品一致的经过验证的模式，不并置第二套主题或假进度组件。
- [x] 对至少一个核心呈现机制提供冻结数据的开关/旁路对照，报告差异和不能证明的用户体验结论。
- [x] Web 构建通过，核心触点完成实际浏览器检查；触屏、窄视口、键盘及 reduced-motion 状态按实际检查范围报告。

## Design constraints

- 不改变招募链路、API 语义、报告评分或数据来源，以避免把视觉改版混成后端算法变更。
- 进度只来自运行事件，不用计时器假造完成百分比、步骤推进或预计时间。
- 缺失值继续显示为未知；“尚无候选记录”和“没有找到符合要求的球员”不能混为一谈。
- 每次提取模块须让一个清晰的状态所有者或展示职责更易理解；不做仅为文件变小的拆分。
