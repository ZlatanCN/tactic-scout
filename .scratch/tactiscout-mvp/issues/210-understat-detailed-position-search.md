# 210 — Understat 细分位置检索与证据核实

Type: task
Status: resolved
Labels: ready-for-agent

## Objective

让全部 17 种产品位置查询在 Understat 数据粒度下保持语义诚实：细分位置从对应大类召回候选，读取当前赛季位置记录核实后再进入推荐；来源缺少或未返回细分位置证据时保留为未知，不能提前筛空，也不能把大类位置说成精确命中。`mosaic` 中的 Understat 子集遵循同一规则；只有粗位置的 ASA 记录保留为未核实来源记录。

## Acceptance

- [x] Understat 目录大类只作为细分位置的召回范围；搜索观察区分精确位置过滤与位置族召回。
- [x] 细分位置调查先读当前赛季位置记录；原始位置代码、赛季、分钟及直接/相邻/缺失状态保留在候选与报告中。`Sub` 不作位置证据。
- [x] 候选评估、推荐校验、角色位置指标和报告都使用相同的位置证据；未经核实的候选不能伪装成符合细分位置。
- [x] 对细分位置按批调查并使用准确的下一页游标；未达到名单目标或来源范围未读完时继续调查，达到本轮预算后如实标注覆盖与未知。
- [x] 数据源粒度限制不再触发要求用户放宽位置的重复追问；真实改变引援意图的问题仍可追问。
- [x] 验证 17 种产品位置的召回族、Understat 原生位置代码映射、Sub 排除、当前赛季与分钟边界、分页与预算状态，以及完整 LangGraph 报告链路。
- [x] 使用同一冻结候选快照做“严格目录筛选 / 位置族召回 / 位置族召回加逐批位置核实”消融，并只报告召回与调查行为，不宣称已测得真实引援适配度。

## Design notes

- Understat 目录位置字段保留为 GK/DEF/MID/ATT 等粗粒度；球员详情中的赛季位置标签属于出场记录，不是固定战术职责。
- 位置证据可分为直接对应、相邻标签、当前赛季未观察到、详情不可用和待查；“未观察到”与“不可胜任”不同。
- 900 分钟百分位门槛不用于位置资格；位置样本分钟必须单独展示，不能机械设置为能力门槛。
- 首批最多调查 12 名，继续使用现有 LangGraph、Understat SQLite 缓存与 Harness，不新增 Agent 或独立数据管道。

## Answer

Understat 默认模式和 `mosaic` 的 Understat 子集已贯通细分位置的召回、当前赛季核验、按原生位置取指标、候选资格与报告展示；多大类目录行及未知目录位置不会被提前丢弃。`mosaic` 里的 ASA 粗位置记录不会被算成 Understat 精确位置命中；只有 ASA 自己返回与需求一致的细分位置值时，才按其原生位置匹配。Understat 原始目录字段本身也不能绕过详情核验。位置详情接口不可用时会作为待核验限制报告，而不是伪装成预算耗尽、来源没读完或没有符合球员。相邻位置只作为独立线索，不计入目标候选和同位置比较。

同一冻结三人 fixture 的三臂整图消融显示：严格目录过滤发现 0 人并追问 1 次；位置族召回发现 3 人但未核验时不推荐；位置族召回加位置核验发现 3 人、核验 1 批并推荐 1 名有 `MC` 直接证据的候选，均未追问。这验证的是固定输入下的召回与证据门控行为，不验证现实市场召回率或推荐质量。

位置 crosswalk、Understat provider、比较范围和 LangGraph 招募整图定向测试合计 119/119；候选身份整图回归另为 6/6。API 与 Web 构建通过。全套测试 526/528；两项需要绑定 `127.0.0.1` 的 HTTP 测试受当前运行环境 `listen EPERM` 阻止，见[研究记录](../research/understat-fine-position-search-2026-10-16.md)。三臂消融和全链路测试证明的是固定 fixture 下召回、位置证据门控及报告范围，不证明真实市场覆盖或推荐排序准确度。
