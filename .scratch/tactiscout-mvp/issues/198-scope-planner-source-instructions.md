# 198 — 按当前来源收敛 Planner 提示词

Type: task
Status: resolved
Labels: ready-for-agent

## Objective

小范围降低调查及重新规划的上下文负担，用相同模型、冻结样本和整张 LangGraph 对照验证，不增加 UI 状态或改变调查规则。

## Diagnosis

假设优先级：无关来源说明增加输入；较长输出影响生成时间；重复规划增加总调用时间。本轮只改变第一项。

复现接口：`investigationInstructions("understat")`，原提示包含 ASA、FBref、StatsBomb、Wyscout 等非当前来源的长段规则。新增检查先失败后通过。原共享文本含所有来源，现共同控制、来源专属调查说明与来源范围说明分别组合；调查和 reorient 都按实际 dataMode 使用。

## Boundaries

- 不改模型、输出上限、温度、工具预算、Reviewer、筛选和能力评估。
- 不删除当前来源的指标口径、历史范围、缺失值与身份控制规则。
- 对照采用当前 Understat 冻结的 20 条中场记录和空方法/球员报告索引，两臂完全相同；仅测提示词差异，不能代表完整市场或推荐质量。
- 真实耗时是探索性单配对；不能排除前缀缓存和运行顺序影响，不宣称稳定提速。

## Verification

实验版本提示词及整图相关 60 项回归通过，API 构建通过；一次串行全量回归 450/450。随后补充的真实本机 HTTP 请求检查通过，确认调查和 reorient 都实际发送收敛后的提示词。因真实效果不成立，生产源码及这些实验回归均恢复为本轮开始时的内容。

## Answer

尝试不予保留；没有生产代码改动。真实同场景、同模型顺序配对：

- 基线完成：100,624 ms，4 次模型请求；模型决策分别耗时 29,496、7,150、20,560、43,295 ms，工具累计 10 ms。评估 20 条记录，给出 4 条有指标引用的考察线索；输入 11,271 token、输出 621 token。
- 来源提示词收敛版未完成，捕获 `RecruitmentTurnCancelledError`，总耗时 560,256 ms；实验配置总信号时限 240 秒，但此次运行没有在该时限内返回。没有完整结论，不能宣称同等质量或速度提升。
- 基线 Harness 28/29；唯一失败为进度对齐检查。实验脚本误把 progress.turn 标为 0（现有 Harness 使用从 1 开始的轮次），这项不能作为真实产品缺陷或两臂差异。保留原始失败标记，不改写结果为全通过。
- 基线先运行，单配对存在顺序、前缀缓存及机器负载混杂。该实验足以否定本次直接保留优化的理由，不足以证明短提示词普遍更慢。
- 用公开 `createRecruitmentPlanner().decide()` 对不响应的本机 HTTP 模型发出 60 ms 取消信号，三次分别于 63/61/61 ms 退出。未复现单请求取消失效；长整图运行的预算收束原因仍未定位，不把它归因于 LangGraph 或 SDK。

身份无关的原始对照保存在 Git 忽略的 `.data/evaluations/source-scoped-prompt-latency-2026-10-14.json`。临时源码副本、实验脚本和请求探针已清理；用户原有未提交修改保留。

结论：本次不增加抽象或参数。这个样本的主要等待发生在模型阶段，单纯删除非当前数据源规则没有验证收益。后续应针对耗时最长的实际决策请求建立可重复对照，再研究减少无效规划、模型生成行为与负载，而不是继续扩大提示词重构。
