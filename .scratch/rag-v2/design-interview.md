# 新一版 RAG 设计访谈

Status: resolved
Updated: 2026-10-22

用户调用 grill-with-docs，要求讨论一套能实际落地、能在求职面试中解释设计并展示证据的新一版 RAG。本文保留已确认的设计选择；新功能仍需按正式规格实施并实测。

## 已知目标与既有约束

- 求职方向已确认为 Agent 开发；本轮按两三周的投入窗口设计，需要真实实现、可复现的评测、设计取舍与失败样例。
- 后续例行评测和评审不依赖真人逐题评分。当前 AI 面板是既有试点评审事实，不改写成人工评审，也不冒充尚未实现的自动评测流程。
- 用户无法提供第一方观赛记录，不以此作为资料来源或评测标签的交付依赖。
- 已有聊天网关、本地 E5、SQLite 权威原文及 LanceDB 派生索引可供复用；是否调整模型和检索策略将在新的设计取舍中明确。
- 来源处理许可、主体身份、历史样本范围和定性证据边界仍适用；AI 合成评测材料不变成真实球探观察或球员能力真值。
- 之前已允许调整接口和重建索引，不把兼容旧实现作为设计前提。

## 设计树

1. 岗位与项目投入：已确认 Agent 开发、两三周。
2. 业务与语料范围：依赖岗位、投入和现有资料事实。
   - 已选择现有招募 Agent 内的跨资料综合，沿用方法与历史观点两路。
   - 真实获准语料覆盖、资料规模、文档格式与更新方式。
3. 自动评测：依赖业务问题类型和现有标签/评测代码事实。
   - 参考证据的建立、合成问题的校验、数据划分与防泄漏。
   - 可确定性计算的检索/引用/策略检查，以及模型评审的范围和不确定性。
   - 基线、消融、通过门槛、成本与延迟、回归与上线资格。
4. 入库方案：依赖语料与评测需要。
   - 解析结构、切块、上下文补充、元数据、增量更新与撤回。
5. 检索与生成：依赖发现的失败类型、评测方法和运行约束。
   - 查询处理、召回/融合、重排、上下文选择与引用。
   - Agent 编排、重试/降级与预算。
6. 面试交付：依赖前述设计。
   - 可复现演示、对照报告、架构与关键实现、追问材料。

## 事实调查

- 子代理只读核对当前代码、默认运行路径与评测资产；不得把底层构造器默认值直接当作应用入口行为。
- 已确认普通应用入口使用配置工厂，默认 `on_demand`；底层直接构造器仍默认 `fixed`，显式注入 planner 的路径需要另行区分。此前将应用默认行为说成 `fixed` 的说明不准确。
- 当前冻结评测直接调用知识模块，不经过招募触发策略；来源命中标签没有段落级支持区间，不能解释成证据级 Recall@k。
- 子代理从官方文档和原始论文核对无人逐题评审的评测方法、合成数据偏差与模型评审限制。
- 本轮未运行测试或修改 RAG 运行代码。

## 第一轮已确认

- Q1：用户答复「agent 开发」，按 Agent 应用开发的项目展示目标推进。
- Q2：用户选择 B，即两三周的投入窗口。

## 第二轮已确认

- Q3 = B：用户「同意」推荐，在现有招募 Agent 中综合两三篇资料，说明来源差异、适用范围与证据缺口。
- Q4 = A：用户「同意」推荐，自动评审有分歧时允许未决，使相关验收暂不通过；后续修复与重跑不要求真人逐题裁决。生成题包时的争议项在冻结前隔离，冻结后出现的未决项不得从统计中静默剔除。

## 第三轮已确认

- Q5 = A：用户「同意」推荐，本轮支持结构化来源（首批 PLOS JATS/XML）与 Markdown/纯文本；PDF、扫描件 OCR 和复杂表格不列为本轮必须交付。
- Q6 = A：用户「同意」推荐，初次检索证据不足时，Agent 可在总预算内针对缺口补查一次，最多两轮，足够即停，仍不足就说明缺口；保留单轮方案作对照。

## 已核对的编排约束

- 现有 LangGraph 已有工具执行回到规划的循环，可复用主图；需要调整的是阶段可用动作、按候选名称去重及结果/缺口记录，而非新增一个独立自主 RAG Agent。
- 当前每用户回合只允许一次网关重排预约，第二个不同查询只能走合格混合降级或不可用；新版需明确多查询合并、重排与补查的配额。
- 当前检索与每次原文解析共享十五秒，耗尽会影响先前引用在后续步骤的重新解析；新版需给最终引用核验留出预算并保留可用证据的状态。
- 当前报告观察只接受一个文档 ID，投影选该文档的首个片段；多来源归纳需要支持每条主张关联多个精确引用，不能只增加一个检索轮次。

## 第四轮已确认

- Q7 = B：用户同意累计三十秒，覆盖查询规划、检索、重排、缺口检查和最终引用核验，报告生成另计；调整 ADR-0016 的十五秒约定，见 ADR-0021。
- Q8 = B：用户明确改为本轮只复用当前网关模型做离线题目生成、核验和答案评审，采用不同角色与隔离上下文；记录同模型相关误差，不增加第二个评审模型。

## 第五轮已确认

- Q9 = A：用户「同意」推荐，允许增加一个本地专用重排候选，与不重排及当前网关模型重排作有界实验；默认策略由质量、耗时和资源实测确定。该模型只负责检索排序，离线答案评审仍遵循 Q8。

## 共同理解与规格发布

- 候选工程默认值：通用 JATS/Markdown 解析、按完整 E5 输入计 token、原文区间参考标注、检索/给定证据生成/真实 Agent 入口三层评测、每条主张关联多个引用、按质量与成本选择检索方案。
- 以上工程默认值已由用户确认；本地重排模型为有界候选实验，最终默认策略由实测决定。
- 正式规格见 `spec.md`，实施 issue 见 `issues/01-automated-retrieval-investigation-and-evaluation.md`；编排/预算及自动评测子代理复核记录在 `design-review.md`。

本设计确认不代表功能已经实现或实测。
