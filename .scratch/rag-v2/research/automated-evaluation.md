# 无真人逐题评分的 RAG 评测：设计参考

Updated: 2026-10-22

本文为设计访谈的事实与候选方案参考，不表示已经选择框架、确定通过门槛或实现新评测。

## 已核对的资料

- [Ragas 合成评测集文档](https://github.com/vibrantlabsai/ragas/blob/main/docs/getstarted/rag_testset_generation.md)与[已有块的输入方式](https://docs.ragas.io/en/latest/howtos/customizations/testgenerator/prechunked_data/)：可从原文生成问题、参考上下文和参考答案，也可保留已有片段元数据。可借鉴记录形态，不必因此引入完整框架。
- [ir-measures 指标定义](https://ir-measur.es/en/latest/measures.html)：Recall@k 依据已知相关结果集合计算召回比例；MRR 衡量第一个相关结果的位置；nDCG 需要相关性标签。前 k 中是否至少命中一个相关结果应另外称为 Hit@k/Success@k。
- [RAGChecker 原始论文](https://arxiv.org/html/2408.08067v2)：将召回、生成和整体表现分别诊断；分块方式会影响以块为单位的标签与指标，其语义支持检查仍依赖模型估计。
- [RAGAS 原始论文](https://arxiv.org/abs/2309.15217)：提供不依赖人工参考答案的自动语义评测思路；没有人工标签不等于评审无误或已经在足球领域校准。
- [MT-Bench 评审模型研究](https://arxiv.org/html/2306.05685v4)：记录顺序、篇幅、自我偏好等偏差；交换对比顺序和提供参考证据能用于缓解部分问题。多次一致本身不证明判断正确。
- [scikit-learn 数据泄漏指南](https://scikit-learn.org/stable/common_pitfalls)与[AWS 重复样本划分指南](https://docs.aws.amazon.com/prescriptive-guidance/latest/ml-operations-planning/splits-leakage.html)：冻结验证题应与开发调参隔离，同事实、重叠证据和近重复改写需要分组处理。
- [ARES 原始论文](https://arxiv.org/abs/2311.09476)：其预测校准包含人工标注部分；本项目若省略该部分，不借用其校准效果宣称。

## 对本项目的推论，待设计确认

1. 参考证据保存到不可变原文版本及区间，而非只保存块 ID；切块方案改变后重新映射到块，避免把正确答案的定义随实验一起改变。
2. 引用存在、原文逐字匹配、结构化值、策略过滤、耗时和实际 token 用量可由程序校验；语义相关、主张支持和自然语言完整性仍属于模型评估，报告中保留二者的来源区别。
3. 区分检索单独评测、给定参考证据的生成评测、以及真实 Agent 入口的端到端评测。当前冻结 runner 直接调用知识接口，未证明应用是否正确触发 RAG。
4. 合成题和参考标注需保留生成模型、核验模型、提示版本、资料版本及争议状态。来源引文逐字存在不代表它必然支持参考答案。
5. 从待检索语料生成问题，可以合法测试库内问答；泄漏风险在于冻结题参与调参/训练/提示样例，或合成问答被放回检索库。若另行声称未知来源泛化，才需要来源级留出实验。
6. 同一模型的多次独立调用可能共享错误，不称为独立真人评审。可复用网关提供不同任务角色，模型独立性和额外调用成本仍待确认。
7. 只有四份活动文档和 24 道题的既有试点不足以支持宽泛质量宣称；增加同一事实的改写不等于增加知识覆盖。

## 分歧处理需由用户选择

候选建议：题包生成阶段有争议的记录进入隔离区；冻结题的评测出现分歧时记为未决，并明确计入报告与验收规则。不能在运行后移除困难样本来提高通过率，也不能把多数模型投票自动解释为事实真值。
