# 05: Agent 能针对资料缺口补查一次

Type: task
Status: open
Labels: ready-for-human
Blocked by: 03: 招募报告中的一条主张可以引用多处原文。

## What to build

招募 Agent 首轮检索后能识别尚缺的事实，围绕原问题和原样本范围补查一次；仍无证据时带着已取得的引用和明确缺口继续报告。

## Acceptance criteria

- [ ] SQLite 调查账本持久保存调查 ID、查询轮次、主体/时间范围、调用预约及结果状态；LangGraph checkpoint 引用该账本，不另存一份冲突的正文状态。
- [ ] 首轮最多三个子查询，补查最多两个；相同查询/过滤复用已完成结果，失败与零命中区分，完成状态未知的外呼不自动重发。
- [ ] 两轮、恢复和重试共用 30 秒；一次调查最多四次额外网关实际派发，重排按轮批量执行并验证返回候选集合。
- [ ] 统一预算由一个 owner 管理，任务调用使用子预约并给最终引用核验留出额度；并行查询不重复消费同一段 wall-clock 等待。
- [ ] 达到证据要求即停止；用尽轮数/预算后输出部分证据和缺口，不因模型建议继续而产生无限循环。
- [ ] 通过一个两来源招募案件验证问题拆解、首轮、补查、引用累计、不可用结果、进程恢复和 30 秒上限。
