# TactiScout 新版资料综合与自动评测

Status: approved-for-implementation
Labels: ready-for-agent
Updated: 2026-10-22

## Problem Statement

TactiScout 已有方法资料与历史球员分析的检索能力，但目前一次调查难以围绕明确缺口补查，也不能把一条报告结论稳定地关联到多份原文。入库集中在少数结构化资料，按字符切块不能保证 E5 的完整输入不被截断。现有 24 题试点评测按来源命中计数，没有原文区间级检索标签；语义评分依赖本轮 AI 面板，不能构成后续无需逐题人工评审的自动验收流程。

面向 Agent 开发求职，项目需要一条可重复运行的资料调查与自动评测路径，让维护者展示检索/排序对照、真实失败案例、预算控制、引用依据和自动验收边界。现有试点范围小，评测分数不能描述为一般足球问答准确率或球员能力真值。

## Solution

扩展现有招募 LangGraph 的资料综合调查阶段：模型根据本轮的明确问题与已返回证据提出有界子查询；系统先执行一轮混合检索，检查已覆盖事实与缺口，最多针对缺口补查一轮。两轮共享三十秒资料调查预算，能支撑每条报告主张的多个精确原文引用。首批入库支持获准的 JATS/XML 资料、Markdown 与纯文本；稳定保留来源授权、章节结构、历史样本及原文位置。

建立全自动、无需真人逐题评分的评测：从获准语料产生带原文区间和核验记录的合成题包，按事实组隔离开发题与冻结验证题；分别测检索、给定参考证据时的回答、真实 Agent 入口的端到端表现。程序负责可确定的引用、权限、预算和检索指标；当前配置的同一个网关模型使用隔离角色评审语义支持与拒答。评审分歧或不确定记为未决，并使相应质量资格不通过。评测结论标为自动评估，不代表真人或专家验证。

## User Stories

1. 作为招募分析者，我希望让 Agent 综合两三份方法资料或历史球员分析，从而回答现有语料允许回答的多资料问题。
2. 作为招募分析者，我希望报告解释不同来源之间的共同点和差异，从而能区分来源事实与 Agent 的归纳。
3. 作为招募分析者，我希望每条重要结论附有一组精确原文引用，从而能够查看完整支撑该结论的多个段落。
4. 作为招募分析者，我希望报告标出作者、章节、资料类别、发布日期、赛事和样本范围，从而理解资料的适用边界。
5. 作为招募分析者，我希望一条跨资料结论的引用集合失效时，该结论重新核验或被抑制，从而不会留下失去关键证据的完整措辞。
6. 作为招募分析者，我希望来源之间确有分歧时分别看到双方观点和依据，从而不会读到未经支持的调和结论。
7. 作为招募分析者，我希望 Agent 先检查已有结构化证据，再决定是否需要方法或历史分析资料，从而避免无关检索。
8. 作为招募分析者，我希望 Agent 根据首轮证据中的具体缺口提出有限补查，从而查找第一轮没覆盖到的事实。
9. 作为招募分析者，我希望补查保留原问题、核验主体和用户给定的样本范围，从而扩大查询角度时不越过用户约束。
10. 作为招募分析者，我希望资料调查最多执行两轮、共享三十秒上限，从而获得补查机会而不会出现不受限循环。
11. 作为招募分析者，我希望达到证据目标时提前结束，并在证据仍不足时说明缺口，从而不会把“又搜了一次”说成已经找到答案。
12. 作为招募分析者，我希望看到未尝试、语料未覆盖、成功未命中、部分证据、预算耗尽和服务故障等不同结果，从而知道调查实际完成了什么。
13. 作为招募分析者，我希望历史球员分析一直带着赛季与样本边界，从而不会将历史观点说成当前球员能力事实。
14. 作为招募分析者，我希望项目作者摘要与论文原文保持不同的内容归属，从而能核对某项说法由谁撰写。
15. 作为招募分析者，我希望没有足够证据时只说明资料缺口，从而不会从模型记忆、未收录比赛或统计字段缺失中补出事实。
16. 作为资料维护者，我希望通过许可清单导入可用的 JATS/XML、Markdown 与纯文本，从而扩充资料而不将 PLOS 的单一段落规则硬编码到所有来源。
17. 作为资料维护者，我希望 JATS 导入保留嵌套章节、段落、交叉引用和 locator，从而引用和检索保留文章结构。
18. 作为资料维护者，我希望 Markdown 导入保留标题、列表等明确结构，从而不用先把资料压平成无出处文本。
19. 作为资料维护者，我希望不可读或未获准的表格、图片、参考文献等仍按来源规则排除，从而解析器不会扩大授权范围。
20. 作为资料维护者，我希望 chunk 切分使用完整 E5 tokenizer 计算前缀、正文和特殊 token，从而保证实际 embedding 输入不被静默截断。
21. 作为资料维护者，我希望稳定来源重复导入不产生新内容版本，从而幂等重跑不会无故使索引失效。
22. 作为资料维护者，我希望内容、许可或解析范围发生变化时生成有依据的新版本，从而旧引用仍指向原来的不可变文本。
23. 作为资料维护者，我希望新建索引先通过内容、向量和来源政策校验再发布，从而失败的构建不会破坏旧活动版本。
24. 作为资料维护者，我希望重复注册、内容等价重建与真实策略变化能区分开，从而只有语义相关变化才使验收资格失效。
25. 作为运行维护者，我希望资料调查的 SQLite 账本记录每轮查询、外呼、状态和结果，从而 LangGraph 暂停恢复不会重置预算或重复未知外呼。
26. 作为运行维护者，我希望完整资料调查最多进行一次批量网关重排，输出仅重排给定候选，从而模型调用有界且不能制造引文。
27. 作为运行维护者，我希望能把一个小型本地重排模型与混合基线、网关重排做对照，从而由真实质量、耗时和资源结果选择默认方案。
28. 作为评测维护者，我希望每题绑定不可变原文的一个或多个支持路径，从而指标不因 chunk 长度变化而重新定义正确证据。
29. 作为评测维护者，我希望必要事实、可替代支持路径和跨多个片段的完整支持分别编码，从而“命中一个相关块”不冒充已找齐答案。
30. 作为评测维护者，我希望来源命中、片段排序、原文区间覆盖、所有必要事实齐备分别报告，从而能定位召回和上下文组织问题。
31. 作为评测维护者，我希望题目生成、参考核验和答案评审保留 AI 生成来源和提示/模型版本，从而自动标签不会伪装成人工标签。
32. 作为评测维护者，我希望开发题与冻结验证题按事实和重叠原文区间分组，从而同一事实的改写不会跨组夸大泛化表现。
33. 作为评测维护者，我希望冻结题中的未决结果留在分母并阻止对应资格，从而不能通过移除困难题来提高分数。
34. 作为评测维护者，我希望答案评审模型角色隔离且能引用核对依据，从而减少题目、生成答案与评分过程相互污染。
35. 作为评测维护者，我希望同模型的语义评分明确报告为自动估计，从而不把重复的 AI 调用说成独立真人共识。
36. 作为评测维护者，我希望错误引用、错年份、错数值及正确答案控制题也通过评审检测门槛，从而一个不可靠的自动评审模型不能单独批准质量发布。
37. 作为评测维护者，我希望检索、oracle 生成、实际 Agent 调查与系统行为分开统计，从而区分召回失败、生成失败和编排失败。
38. 作为评测维护者，我希望固定基线和候选在同一资料、题目和运行窗口比较，从而可解释排序/补查带来的增益与开销。
39. 作为评测维护者，我希望运行前看到全流程最坏调用清单和 token 上限，从而超预算时在派发前停止而不自动缩减验证题。
40. 作为项目维护者，我希望完整运行被打断或未决时没有验收记录，从而不完整产物不能取得降级资格。
41. 作为项目维护者，我希望通过资格记录绑定语料、策略、索引、模型与提示签名，从而候选结果只作用于它实际评估的版本。
42. 作为项目维护者，我希望既能用自动指标做持续回归，也能保留清楚标记的 AI 面板历史结果，从而理解 v1 试点与 v2 自动评测的关系。
43. 作为项目维护者，我希望保留命令、配置、失败题和结果报告，从而在面试中可重复演示并解释局限。

## Implementation Decisions

- **业务入口**：沿用现有招募 LangGraph；将调查计划、轮次、缺口和调用额度写入 SQLite 持久调查账本，图 checkpoint 保存稳定账本 ID、引用和必要摘要。调查内部使用有界流程，避免每个子查询重新调用完整通用 Planner。
- **调查限制**：首轮最多三个子查询，补查最多两个；两轮共享一个三十秒预算，外部网关最多四次实际派发尝试（一次规划、最多两次重排、一次缺口检查），隐藏重试和格式修复也计额度。至少为最后的原文引用核验留出预算；报表最终生成独立计时。具体子预算先记录在版本化配置。
- **批量与重排**：每个子查询使用同一向量/全文 RRF 基线；每轮合并并按查询归属保留候选后最多排序十二个唯一片段。比较无重排、现有聊天网关排序和一个本地 ONNX Cross-Encoder 候选；只有通过相同题包的质量与系统评测才选择默认排序策略。
- **入库**：将特定论文段落逻辑替换成通用获准 JATS 章节处理，并支持 Markdown AST 与纯文本段落。SQLite 保留规范化正文版本和当前有效来源策略，LanceDB 保存可重建索引。对授权排除内容仍严格排除。
- **分块**：使用实际 E5 tokenizer 校验 `passage:` 前缀、已选元数据和正文总计不超 512 tokens；保留结构优先、句界拆分与原文定位。所有检索候选保持未改写原文，新增检索前缀与规范化正文分开存储。
- **多引文合同**：每条报告主张包含 `claimId`、文字、陈述/归纳类型、样本限制和一个或多个精确引用。引用包含 source/document revision/section/start/end/text hash；一个主张的引用集合可共同支持它。交付前重新核验，任一必要引用撤回/失效时抑制依赖该引用的主张。
- **自动题包**：使用获准原文生成 `synthetic_ai_checked` 题，保存规范化来源版本、精确支持区间、必要事实组、替代支持路径、处置标签与生成/核验来源。以不少于 80 道题、40 个独立事实组、6 个独立文章来源作为试点就绪目标；不足时标记未就绪，不用改写同一事实凑数。
- **划分**：将同事实、近重复题和重叠支持区间组成事实组，再以约 60:40 划分开发/冻结验证。被检索资料可以包含基准原文，但冻结问题、答案和参考标注不进入检索索引、训练或开发提示样例；只报告库内 QA 能力，不宣称未知来源泛化。
- **三层评测**：检索单独评测原文区间和必要事实组覆盖；给定参考证据单独评测生成；完整题包使用普通招募 Agent 入口评估两轮、引用和缺口状态。额外执行少量 JSON/SSE 案例及恢复、失败和取消行为。单独知识 Reader runner 不算作应用入口覆盖。
- **评测角色**：题目生成、题包检查、答案评审只使用当前配置的网关模型，采用隔离角色和独立上下文并记录模型/提示版本。两位同模型评审一致支持才通过、一致不支持为失败、分歧或任一不确定为未决。评审语义不当作客观真值。
- **指标和验收**：必要事实是 AND、替代支持路径是 OR、每条路径内原文片段是 AND；完整覆盖根据同版原文区间并集判定，忽略结构切分留下的纯空白，不以部分重叠算支持。辅以按索引版本固定相关块映射的 Recall@k/Hit@k/MRR，并报告其仅覆盖已标注证据。
- **项目验收目标**：权限/身份/引用/轮次确定性违规为零；支持率（可答/部分可答题）≥90%、宏平均必要事实覆盖≥85%、拒答处理（部分可答/不可答题）≥90%；受控评审正例通过≥90%、错误控制无错误放行。统计含失败/未决/超时及分母，未知单价不换算费用。验证前锁定门槛；模型评审控制未通过时不发布语义资格。这些是已确认的项目目标，不是行业标准或已达到的成绩。
- **非退步**：固定基线为新语料及新证据合同下的单轮混合检索、无专用重排、相同生成模型。候选必须达到门槛、总体和有足够样本的任务类别指标不低于基线、无新增关键违规；逐题进退均公开。质量无可靠收益时保留更简单的合格基线。
- **预算与发布资格**：生成全流程调用/Token manifest；快跑上限 100 次、完整流程上限 1,300 次（用户于 2026-10-23 明确授权提高上限以完成整套预注册阶段）。超限在开始前拒绝，冻结题和评审数量不能自动减少；执行中断不产生验收记录。内容等价重建只有在有效策略及规范化原文、分块、embedding 和派生向量清单均匹配时才可沿用组件资格。

## Testing Decisions

- 只验证公开行为：资料准入/解析、token fit、跨片段检索、两轮停止/预算、多引用解析、自动评测分母/未决控制和应用回合输出；不把内部方法私有函数测试当作质量证明。
- 知识模块检索/解析以 `tests/knowledge/knowledge-evidence.test.ts` 先例为主，使用真实临时 SQLite/LanceDB 和明确注入的确定性模型/时钟。
- 题包、指标、自动评审与验收签名以 `tests/evaluation/rag-evaluation.test.ts`、`tests/evaluation/rag-ai-panel-review.test.ts` 先例扩展；覆盖原文区间跨块完整覆盖、替代路径、分母保留、控制失败未决、预算预检与模型输出结构校验。
- 招募图运行以 `tests/api/recruitment-conversation-api.test.ts`、`tests/recruitment/conversation-turn-runtime.test.ts` 为先例，至少有一个真实应用装配的 JSON/SSE 调查场景、两轮补查、来源失效抑制依赖主张和进程恢复。
- 回归测试使用可控 fake gateway、local ranker 和已登记源，不访问外网、不下载模型；真实网关/语料结果作为显式离线评测产物，不能冒充 CI 测试。
- 发布资格测试验证完整签名匹配、过期/撤回源失效、同内容重建可核对、不同模型/提示/策略不沿用错误的资格，以及任何超预算/中断/未决都不产生新接受记录。

## Out of Scope

- 第一方观赛记录输入、当前全量球员/近期球探报告覆盖、球员能力或转会效果真值。
- PDF、扫描 OCR、复杂版面/表格恢复、通用上传文档问答产品。
- RAPTOR、GraphRAG、独立目录浏览 Agent、模型微调或把源文摘要变成能力统计。
- 第二个 AI 评审模型、真人逐题评审、真人校准或专家真值。
- 新部署 Cross-Encoder 服务；只比较复用现有 Node/ONNX 环境的本地候选模型。
- 将同模模型评分宣称为人类独立共识、具普遍校准的准确率，或基于小样本宣称跨来源泛化。
- 采购数据、自动联系出版方、抓取许可不明来源，或超出各来源准入记录的内容范围。
- 本规格不包含已实现的代码、已通过的端到端质量数据或已知准确率。

## Further Notes

- 当前 AI 面板试点和早期人工评审保留各自原始评审类型；新自动评测建立新的证据记录，不重标历史结果。自动模型评审仍是模型估计。
- 方案符合 [ADR-0001](../../docs/adr/0001-report-retrieval-as-qualitative-evidence.md)、[ADR-0002](../../docs/adr/0002-permission-gated-scouting-corpora.md)、[ADR-0015](../../docs/adr/0015-rag-dual-corpus-first-release.md)、[ADR-0018](../../docs/adr/0018-canonical-rag-evidence-and-derived-indexes.md)、[ADR-0020](../../docs/adr/0020-automated-rag-evaluation-preserves-unresolved-results.md) 与 [ADR-0021](../../docs/adr/0021-bounded-rag-research-with-thirty-second-budget.md)。
- 已批准的用户取舍、主要问题和访谈状态见 [design-interview.md](design-interview.md)；初始语料候选、E5/JATS 与本地排序模型事实分别见 `research/`。实现实际来源前仍须执行每个来源的准入和排除规则。
