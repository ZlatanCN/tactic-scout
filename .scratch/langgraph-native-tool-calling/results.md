# LangGraph 原生工具调用对照记录

**结论：本次对照无效于“哪种协议更好”的结论，不能宣称原生工具调用更快、更省 token 或推荐质量更高。** 两种协议都没有稳定完成全部场景检查。

## 运行配置

- 模型：`codex/gpt-6-luna`，通过已配置的本机网关调用
- 数据：curated 固定快照 `6f9c45c889d5ae553d1b395d87dd3ad6d1bac8dcf21c3cdadbcb627d14e8be4f`
- 场景：`barcelona-under-23-midfielder`
- 对照：旧版 JSON action + 手动分发；原生 `bindTools()` + LangGraph `ToolNode`
- 每臂 3 次，交错配对；原始记录在 [harness-results.json](./harness-results.json)

## 发现

1. 最初用“凯恩接班人”场景启动时，两臂都在追问阶段结束，6 次运行均为 0 次 Planner 请求、0 次工具调用。它不适合验证工具协议，不能算作消融结果。
2. 改用清晰的巴萨中场需求后，旧版前置运行实际进行了 3 次 Planner 请求和 5 次工具调用，但最后以 `RecruitmentPlannerOutputError` 结束。最初的前置门槛只检查“是否调用过 Planner 和工具”，错误地继续运行了 6 条配对链路。这是 Harness 的缺陷，已改成必须先得到无错误的完整报告，否则在配对前停止。
3. 六条已运行链路全部未通过完整 Harness 检查：

| 协议 | 通过 | Planner 请求 | 工具调用 | p50 / p95 耗时 | 失败情况 |
| --- | ---: | ---: | ---: | ---: | --- |
| 旧 JSON action | 0/3 | 10 | 15 | 13.7 / 18.5 秒 | 2 次结论阶段上下文超限；1 次 Planner 响应错误 |
| 原生工具调用 | 0/3 | 9 | 13 | 12.6 / 14.1 秒 | 1 次上下文超限；1 次 Planner 响应错误；1 次有报告但 4 项场景检查失败 |

部分运行的 token 用量不完整，两个通过率都是 0/3，报告也未稳定生成。因此耗时、调用数的差异可能只是失败位置不同，不能解释成效率收益。原始 JSON 中的 `experimentInformative: true` 是旧前置门槛产生的字段；应以本报告的“不具备比较结论”以及已收紧的实现为准。

## 可以确认的内容

- 原生路径确实向模型发出了具名工具调用，并实际经过 `ToolNode` 执行；完整图行为测试通过。
- 这证明接线可运行，不证明生产链路已经可靠。下一次有效消融前，必须先让基准场景稳定完成并修复报告阶段的上下文容量与 Planner 响应问题。
- 更新后的 Harness 会在模型实际调用配对两臂前验证基准完整产出；场景不适合或报告未完成时，会记录阻断原因并停止。

## 2026-10-20 更新：修正预检偏差并重跑

前述 Harness 的预检要求旧协议必须先成功，存在方法偏差：旧协议控制臂若在预检失败，其失败率就不会进入配对样本。现在预检改用产品默认的原生 `bindTools()` + `ToolNode` 路径；只有当前产品链路无法完成完整报告时才阻止实验。旧协议错误作为配对结果保留。CLI 回归覆盖了预检协议，固定数据快照和场景没有改变。

原始新结果：`.data/evaluations/langgraph-native-tool-protocol-luna-current-20261020-v9.json`。原生路径预检通过（2 次 Planner 请求、7 次工具调用、完整报告），随后完成 3 组交错配对：

| 协议 | Harness 通过 | 完整报告 | Planner 请求 | 工具调用 | p50 耗时 | 实际总 token |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 旧 JSON action + 手动分发 | 2/3 | 2/3 | 均值 1.00 | 均值 4.00 | 8.0 秒 | 51,184（6 次请求） |
| 原生具名工具 + ToolNode | 3/3 | 3/3 | 均值 1.67 | 均值 6.33 | 11.8 秒 | 76,726（8 次请求） |

实验仍标记 `inconclusive`：第一组旧协议在任何 Planner/工具调用前追问并停止；剩下两组虽然双方都通过场景检查，但推荐顺序和引用证据顺序在两组中都不同。没有可信球探排序标签，无法说哪个排序更好；样本也不足以把请求数、token 或约 3.8 秒的 p50 差异解释为因果效率收益。当前能确认原生路径完整工作且 Harness 可公平纳入旧协议失败；还不能宣称原生协议在真实工作负载下更好或更快。

下一步仍未完成：加固工具响应协议/问题需求追问的稳定性，或在固定模型和场景上扩大重复样本；在协议失败和排列波动仍存在时，不据此次消融做“更优”结论。产品保留原生 ToolNode 路径，因为 LangGraph 接线和整图回归已验证；这次 Harness 对照尚未证明它相对旧协议的质量或效率收益。
