# 通用球员身份解析

Status: complete

## 目标

将召回、消歧、资料关联分开：本地球员可在外部服务故障时被识别；中文译名、外号、错字允许模型提出候选，但模型与搜索热度不能直接确认身份。复用现有 LangGraph interrupt、身份选项和球员仓库。

## 验收

1. 本地精确名称/已验证别名优先，来源记录标识可直接关联画像；同名记录不按名字合并，不误排除另一人。
2. 多路候选统一去重和消歧；模型变体与网络线索只能召回，未证明原称呼关联时给出具体候选确认。
3. 显式身份线索（球队、位置、国家、年代）参与候选解释/排序；招募目标球队不自动充当参考球员球队，旧画像不当作当前效力。错误或冲突上下文不强行认人。
4. 联网命中两个域名不足以自动认人；不能把模糊英文候选中的一个实体提升为原始称呼的唯一身份。
5. 已核实多语言别名可持久复用；用户确认保留会话作用域，跨会话仅作为待确认线索，不变成全局唯一别名。一个别名可对应多人；保存依据、时间和作用域。正/负缓存有独立 TTL，故障不缓存为未命中。
6. 名称不变但补充有效线索或重试时可继续解析，避免失败结果永久卡住同案；“都不是，重新找”由结构化答案直接触发重查并排除已拒绝实体/来源记录，不要求模型先猜用户控制意图。取消信号全程传播。
7. 前端沿用身份选择卡，支持本地记录、可辨别的出生年份/位置信息，不伪造 Wikidata 链接；提供明确的“都不是，重新查找”按钮，也允许用户补充线索。
8. 固定场景配对消融本地索引、模型召回、上下文、联网，记录正确召回、误认、确认次数、记录关联、调用/耗时；含同名、外号、错字、错误线索、球队变化、库外球员。实机验证中文例子与选择恢复。合成数据消融只证明机制改变了预期行为，不外推模型真实准确率或任意球员效果。

## 设计约束

使用 codebase-design 的深模块：一个带上下文的 resolver 接口，内部复用现有本地索引、Wikidata/Tavily 和 ChatOpenAI；SQLite 只记录名称解析证据，不建立全球知识图谱，不添加向量数据库。保留所有此前工作区改动。模型、网络异常不被误报为空市场。

## 验证记录

- 冻结合成场景：8 个配对场景、5 个实验臂。完整方案正确召回 7/8、首次选择正确 7/8、自动误认 0；关闭本地索引为 5/8，关闭模型召回为 4/8，关闭上下文为 6/8 且发生 1 次自动误认，关闭联网为 5/8。该实验只验证预设机制在固定样例上的行为变化，不代表真实球员库准确率或生产延迟。
- 本机 Qwen 结构化理解检查：4/4 语义断言通过，覆盖拒绝候选、要求重查、替代者不得臆造位置、引用线索须有原文依据。
- 隔离浏览器手测“推荐类似切尔基的球员”：候选确认卡支持“都不是，重新查找”；拒绝后系统排除刚拒绝的候选并询问球队、国家、位置或年代线索。测试使用独立 localhost origin，没有修改用户 127.0.0.1 origin 的浏览器数据。
- 自动化回归：621/621 测试通过；`pnpm build` 和 `pnpm build:web` 通过；`git diff --check` 通过。
- 尚不能据此声称任意中文译名、外号或错字都能识别。低置信度时追问和可恢复重查是产品正确性的一部分，不应为追求表面召回率而猜人。
