# RAG 重构实现补充说明

Status: supporting-design

日期：2026-10-21。

用户已显式调用 to-spec，正式范围、决策和验收要求已发布到同目录的 spec.md，并标记 ready-for-agent。本文保留实现展开作为补充，冲突时以正式规格为准；不再等待额外访谈，规格发布不代表运行实现已经完成。

## 1. 交付范围

- 同时实现方法资料与球员定性观察两路，保留不同资料用途、适用范围和来源类型。
- 球员路线使用获准外部资料，不依赖用户提交第一方观赛记录。
- 首批可以采用外部研究者针对具名球员历史比赛的分析观点，明确作者、样本比赛和时间；这是检索、引用和历史范围识别的真实资料试点，不证明现役引援效用。
- 按需触发检索：方法解释、用户明确报告请求或已评估候选的定性资料需求；取消每轮/每批固定检索。
- 复用现有聊天网关承担生成与有界批量重排，本地 multilingual E5 负责 embedding。
- 每个用户回合的所有运行时 RAG 工作共享累计 15 秒额外等待预算；模型准备和离线入库在调查前完成。
- 网关重排失败时可以使用独立验收通过的混合检索基线，保留排序模式和失败原因；其他权限、身份、时间及证据检查照常执行。
- 首轮合计 20–30 个代表性问题进行人工复核；用户负责判断回答及引用，不负责采集观赛记录。
- 允许调整内部接口并重建索引，不迁移旧知识索引或旧 RAG 引用格式。

## 2. 推荐工程形态

一个知识证据模块对调用者暴露检索与引用解析两个操作，内部管理资料版本、检索、上下文和处理权限，不引入第二张检索 Agent 图。

```text
核验来源与原始资料
  -> 结构解析与不可变文档版本
  -> 章节/段落/原文区间
  -> 检索块及 embedding
  -> 暂存 LanceDB 索引
  -> 校验后发布活动索引版本

问题 + 已确认的球员/时间范围 + 服务端访问上下文
  -> 当前来源与版本筛选
  -> LanceDB 向量召回 + 原生 BM25
  -> RRF 融合、去重
  -> 预算允许时使用网关批量重排
  -> 片段适用性与来源复核
  -> 必要原文上下文与可解析引用
  -> Planner / 报告
```

### 权威存储与派生索引

推荐以 SQLite 保存权威资料、不可变版本和有效处理策略，LanceDB 保存可重建的全文/向量索引。最小权威结构包含来源策略、文档版本、原文块、索引发布记录，以及有界检索结果/重排调用的幂等记录；不建立额外通用文档管理或工作流平台。

Git 中可继续保存便于审阅的来源声明，显式导入并发布后才成为 SQLite 中的有效策略。运行时只读取这一份有效策略，不能由 JSON 与数据库分别决定准入；删除/撤回等命令更新有效策略并留下记录，重启不能从旧声明自动恢复已撤回权限。

SQLite 先写暂存版本，构建并检查 LanceDB 索引后，再通过事务切换活动索引版本。构建失败的暂存资料不参与查询；索引损坏时可从权威记录重建。仍获准留存且已被案件引用的不可变原文版本独立于当前索引保留。

### 文档与原文定位

每份文档保留来源、作者、许可、原始链接、语言、发布时间、资料类别、球员身份与样本比赛/赛季，以及原始内容 hash 和解析规则版本。

每个原文块保留章节路径、段落序号和不可变规范化文本。证据引用使用 `documentRevisionId + blockId + startOffset + endOffset + textHash`，区间以该不可变 JavaScript 字符串的 UTF-16 code unit 计数。LanceDB 行 ID 或当前索引 generation 不能单独充当持久证据引用。

用于引用的 `evidenceText` 与用于搜索的 `retrievalText` 分开：后者可加入标题、章节路径、核验过的实体名和样本范围，前者始终回到原文。模型生成的解释不写回原文。

### 切块

第一版解析已登记论文 XML、Markdown/文本分析资料及现有结构化观察格式，优先保留标题、完整段落、句子、列表和样本范围。每个子块初始目标 200–350 个 E5 tokens，包含检索前缀后的总输入须在模型窗口内；最多重叠一个短段落，不跨不相关章节。

来源特定排除规则优先：某来源不允许的图、表、补充材料或第三方内容不因通用解析器支持而进入索引。仅在原文需要时补充同一章节的标题和相邻原文，不生成推测性背景前缀。

## 3. 最小调用接口

```ts
interface KnowledgeEvidence {
  retrieve(
    request: EvidenceRequest,
    context: EvidenceAccessContext,
    signal?: AbortSignal,
  ): Promise<EvidenceBundle>;

  resolve(
    refs: EvidenceRef[],
    context: EvidenceAccessContext,
    signal?: AbortSignal,
  ): Promise<EvidenceBundle>;
}
```

- `EvidenceRequest` 区分方法资料与球员定性资料，携带问题以及已确认的主体、样本/时间需求；不允许模型指定来源权限或自行确认身份。
- `EvidenceAccessContext` 由应用装配，包含处理目的、当前模型目的地、访问范围及当前回合共享预算。元数据过滤由知识模块编译，调用者不拼接检索 SQL。
- `EvidenceBundle` 包含结果状态、逐主体资料覆盖、原文片段、引用、来源与样本限制、使用的排序模式和安全 trace 标识。
- 结果区分取得资料、未触发、试点未覆盖、成功未命中和不可用；超时、来源失效或服务失败不解释成没有相关事实。
- `resolve` 从权威原文重新加载引用，检查 hash 和当前处理权限；原版本不可用时明确返回，不悄悄换成最新版本。
- 入库、来源发布、撤回和索引构建通过管理入口完成，与 Agent 的只读接口分开。

## 4. 检索与运行预算

推荐的起始参数是向量与全文各取 Top 30，RRF 常数 60，去重融合后最多 12 个片段交给一次网关批量重排，最终方法资料最多返回 6 条。它们是实现起点，通过冻结评测调整，不是效果承诺。

使用 LanceDB 原生全文索引和向量查询，不再将全库正文载入内存逐篇计算 BM25。中英文分词采用已验证的 ICU 配置；查询可使用审核过的双语术语映射，但首版默认不增加 LLM 查询翻译/改写调用。

移除当前把中文词项覆盖率强制施加于英文原文的来源级硬门槛。相关性在片段层判断；一份文档的某个片段相关，不能让同来源其他片段自动通过。方法资料和球员资料分别校准采用/拒答规则，原先 `0.812 / 0.5` 数字不直接沿用。

球员资料按主体分别记录覆盖与候选，优先使用已核验的球员实体或来源 ID 关联；模糊姓名不能自行合并身份。有限结果预算下未处理的主体明确记为未处理，不混为零命中。

### 网关调用

- 初始默认整回合最多一次新增网关批量重排；其他检索使用基线或已完成的同请求结果，不自动反复重排。
- 重排候选均来自已过滤的真实片段，模型只返回候选 ID、顺序和有限的相关性标签，不返回改写原文。
- 相关性标签不是事实核实结论；资料中的研究者解释仍保留观点与样本限制，程序对引用存在性和范围的校验也不能代替人工判断原文是否支持回答。
- JSON 无效、未知/重复 ID、候选集合不符、超时或服务故障均作为重排失败，转入已验收基线；不能修补出模型未返回的证据。
- 重排调用初始上限为剩余共享预算与 8 秒中的较小值，为上下文返回保留余量；该额外任务不使用 Planner 足球动作提示词，也不叠加隐式多层重试。
- embedding、索引查询、重排、原文加载与上下文组装都计入同一回合 15 秒累计等待预算，所有调用共享剩余额度。运行前预备本地模型与索引，避免首个用户请求临时下载/入库。
- 请求取消后停止后续阶段并丢弃未提交结果；无法协作取消的本地调用不能被描述成已实际中止。

独立记录检索与重排的阶段耗时、输入/输出 token 覆盖、候选计数、排序模式与降级原因。外部日志默认不输出原始提示词、私有原文或隐藏推理。

## 5. LangGraph、案件恢复和资料撤回

保留图中的检索工具动作，由工具适配器调用知识证据模块。图状态保存选中证据引用、检索 outcome、trace ID、索引版本、排序模式和已用预算，不将整批正文反复追加到 checkpoint。

每次给模型组装资料上下文及交付引用前重新 `resolve`。案件恢复可以解析已完成结果的引用，不必重新调用重排；使用已有请求/回合及动作序号形成幂等标识，避免图重试重复执行已完成的重排。

当前来源策略同时作用于新检索与旧引用解析。撤回后先禁止新处理，再清理派生索引；如果留存本身也不再允许，则删除相应正文并保留最小失效标识。旧引用不可解析时展示明确状态，不将失效资料继续放进新模型上下文。

历史成品报告与新的模型输入分开处理：只保存引用不意味着能擦除用户此前保存到浏览器的成品报告，不把来源撤回说成远程删除所有历史副本。

## 6. 球员历史试点的真实接入范围

首批候选来源改为项目已登记、可通过 PLOS 官方 API 获取且出版方声明 CC BY 的 Mead 等论文（DOI 10.1371/journal.pone.0282295）。只将作者关于 La Liga 中具名球员历史 PlayeRank 样本的原文分析段作为球员定性观点；论文说明比赛数据来自 2017/18 赛季，但没有逐人给出比赛日期。不得把引用的 Wyscout、Transfermarkt/Kaggle、FBref 或 ClubElo 数据随文章另行采集或入库。

原先的 SAGE Evers 等论文不准入首版：出版方另有政策要求将 SAGE 内容用于包括 RAG 的 AI 时持有额外 SAGE 许可；本项目未取得此许可。不得仅根据 CC BY 署名许可覆盖另外声明的 AI/RAG 使用条件。

论文的方法章节与具名球员案例按内容分别归类，整篇方法论文不能直接被标成球探报告。原文中的研究者观点保留论文作者、历史比赛和分析依据，不移植为系统自行计算的当前比赛指标。

历史试点先验收证据模块、真实原文引用和报告资料投影，再核验招募工具适配器的身份与样本规则。现有交互候选池不保证包含论文中的球员：不能为了产生命中把历史人物塞进当前候选池，也不默认新增通用聊天或 UI 功能。候选池没有相应主体时可以返回覆盖范围外，这不算现役引援有效性已验证。

没有资料不评价球员能力；有冲突的来源观点分别保留出处和样本，不自动平均或生成一个客观结论。沿用 ADR-0001：定性资料可以支持后续人工考察优先级和解释，不改写量化指标或填补结构化字段。

## 7. 验收与交付顺序

准备合计 24 个问题作为 20–30 个问题试点的起点，两路各 12 个，覆盖可回答、无答案/未覆盖、中文查英文、错误球员或历史范围干扰。按问题家族分开校准与冻结验证；人工复核最小支持片段、回答是否得到支持及引用是否准确。单篇文章、少数球员和作者标注的限制明确保留。

记录候选/最终片段召回、排序指标、无答案误接受、人工原文支持判断、延迟和 token 用量。旧方案、原生混合检索和新增网关重排分别运行；用于运行时降级的基线也必须独立验收。最初方案中的 95%/85% 等目标尚未被用户确认，不能写成既定通过率或现有成绩。

结构性要求为：引用可解析且 hash 一致、来源/主体/样本检查不能因降级而跳过、撤回资料不能进入新上下文、失败不能伪装成零命中、超出预算不能继续发起额外模型调用。历史试点不能产生当前能力或完整市场覆盖声明。

推荐实现为五个可审阅单元：

1. 固定试点资料、许可范围、问题与原文标签，保存当前基线。
2. 实现权威目录、不可变原文、结构解析及暂存/发布协议。
3. 实现原生全文/向量混合检索、上下文和可解析引用。
4. 实现现有网关批量重排、15 秒共享预算、基线降级与可观察结果。
5. 接入案件状态、恢复/撤回规则和报告投影，完成定向回归、构建及小规模人工复核。

实现中的具体数据库字段、内部文件组织和候选数微调由代理按已确定需求处理，不再逐项要求用户批准。若新增设计会改变上述产品范围、来源用途、预算或资料处理权利，则回到相应设计决策。
