# TactiScout：可追溯的双路 RAG 重构

Status: open
Labels: ready-for-agent
Updated: 2026-10-21

## Problem Statement

招募分析者需要用自然语言理解球员角色、指标含义和比赛样本，也需要为具体球员找到有作者、时间和依据的定性资料。目前方法资料检索虽然保留来源并使用混合排序，但固定字符切块会丢失章节语境，查询时扫描语料计算词项分数不利于扩展，中文查询的词项覆盖门槛还会拒绝部分语义相关的英文资料。检索到某篇文章不代表其中每个片段都能支持当前问题。

球员定性资料存在真实覆盖缺口：访谈时本机索引的 213 个片段全部属于方法资料，球员报告片段为零。用户无法提供第一方观赛记录，因此需要取得可准入的外部原文，并公开限制试点的球员、比赛与历史范围。模型生成条目、搜索摘要或方法论文中的球员姓名不能替代真实的报告观察。

现有检索还缺少独立于向量索引的不可变原文引用、跨索引重建的解析能力、恢复案件时的当前权限检查，以及共享的运行时等待预算。用户希望复用已经配置的聊天网关，得到可停止、可恢复、引用准确且不会把失败说成无资料的调查过程。

## Solution

重建一个独立的知识证据模块，分别检索方法资料与球员定性观察，沿用项目对报告观察、球探观察记录及历史球员分析观点的定义。模块负责结构解析、原文版本、来源处理边界、混合召回、网关批量重排、上下文补全和引用解析；LangGraph 继续负责调查决策、工具动作、暂停恢复及报告，不增加第二个检索 Agent。

首版使用本地 multilingual E5 embedding、LanceDB 原生全文与向量检索、RRF 融合，以及现有聊天网关的有界批量重排。SQLite 保存权威原文、不可变版本和有效处理策略，LanceDB 是可重建的派生索引。招募案件保存稳定证据引用和运行摘要，在重新供模型处理或生成引用前加载原文并检查当前策略。

检索按方法解释、用户明确报告请求或候选的定性资料需求触发。正常运行中，每次用户输入引发的调查回合共享累计 15 秒额外 RAG 等待预算；重排失败可使用独立验收通过的混合检索基线。所有路径继续检查来源、身份、样本时间和证据适用性。

两路首版都要交付，球员路线先使用获准外部资料构建有限真实试点。用户已接受研究者对具名球员历史比赛的分析观点，用来验证检索、引用及历史范围识别；这不证明现役引援效用。项目准备 20–30 个代表性问题、原文支持片段和评分表，由用户或复核者核对回答与引用。

## User Stories

1. 作为招募分析者，我希望用中文检索英文方法资料，从而能够理解相关角色和评估方法而不必自行翻译全文。
2. 作为招募分析者，我希望检索结果保留标题、章节和必要的相邻原文，从而能够理解代词、定义和结论适用范围。
3. 作为招募分析者，我希望方法资料与球员定性观察分别呈现，从而不会把一般研究结论当成某名球员的表现证据。
4. 作为招募分析者，我希望每条资料有作者、来源、原始链接和许可署名，从而能够检查出处并继续阅读。
5. 作为招募分析者，我希望报告引用能定位到具体原文片段，从而能够核对某句话究竟得到了什么支持。
6. 作为招募分析者，我希望系统只采用与当前问题相关的片段，从而不会因同一论文另一个段落相关而收到无关结论。
7. 作为招募分析者，我希望系统在需要方法解释时检索，从而能够补充理解而不为每次调查固定等待相同资料。
8. 作为招募分析者，我希望明确要求球员报告时进行有范围的资料查询，从而能够取得与已评估主体有关的定性线索。
9. 作为招募分析者，我希望已经能由结构化证据回答的问题跳过无必要检索，从而减少重复调用和等待。
10. 作为招募分析者，我希望球员资料绑定经过核验的身份，从而不会把同名球员或相似姓名的观点用于当前候选。
11. 作为招募分析者，我希望不同候选分别记录资料覆盖情况，从而不会把未处理的候选误认为已经搜索但没有结果。
12. 作为招募分析者，我希望清楚看到试点覆盖的球员和资料范围，从而不会把有限语料理解为完整球员市场。
13. 作为招募分析者，我希望历史球员分析观点标明作者、比赛和样本时间，从而不会把历史比赛评价理解为当前赛季能力。
14. 作为招募分析者，我希望研究者的分析与职业球探报告保留不同来源类别，从而能够判断资料究竟支持何种判断。
15. 作为招募分析者，我希望来源中的观点和不确定性被保留，从而不会把作者解释变成已核实的统计事实。
16. 作为招募分析者，我希望不同来源的冲突观点分别展示出处和样本，从而能够自行判断差异而不被一个自动平均结论掩盖。
17. 作为招募分析者，我希望定性线索可以支持后续人工考察优先级和推荐说明，从而知道哪些问题值得继续核查。
18. 作为招募分析者，我希望定性资料不改写比赛指标或填补缺失字段，从而保留量化证据与报告观点之间的区别。
19. 作为招募分析者，我希望没有可用资料时看到明确缺口，从而不会把资料缺失理解成球员能力差。
20. 作为招募分析者，我希望未触发检索、试点未覆盖、成功未命中、查询失败和资料失效保持不同状态，从而能够理解本次调查实际完成了什么。
21. 作为招募分析者，我希望多次检索共同遵守一轮 15 秒额外等待预算，从而不会因工具调用增加而不断延长资料处理时间。
22. 作为招募分析者，我希望网关重排失败时能使用已验收的基础检索结果，从而在资料仍可靠可用时继续调查。
23. 作为招募分析者，我希望没有已验收降级基线时返回不可用状态，从而不会收到未经验证的替代结果或伪造的球员结论。
24. 作为招募分析者，我希望重排降级后来源、身份和时间检查继续成立，从而不会以降低处理质量为由越过证据要求。
25. 作为招募分析者，我希望停止请求阻止后续检索和模型调用，从而能够及时结束不再需要的调查。
26. 作为招募分析者，我希望超时或取消之后到达的计算结果被丢弃，从而不会在已结束的回合里突然增加报告或进度。
27. 作为招募分析者，我希望恢复同一案件时仍能解析已经取得的引用，从而能够延续调查而不重新搜索全部资料。
28. 作为招募分析者，我希望恢复和重试不会重置已用预算或重复重排外呼，从而避免重复等待与模型用量。
29. 作为招募分析者，我希望已撤回资料不再进入新的模型上下文，从而使恢复的案件也遵守当前来源处理边界。
30. 作为招募分析者，我希望旧引用失效时明确显示原因，从而不会在不知情的情况下被替换成另一版原文。
31. 作为资料维护者，我希望通过统一准入流程登记外部来源及其允许的用途，从而能够持续维护真实获准的知识资料。
32. 作为资料维护者，我希望外部球员试点不依赖用户提交观赛记录，从而能够按用户已经选择的资料路线交付。
33. 作为资料维护者，我希望论文的方法章节和具名球员案例按内容分类，从而不会把整篇方法论文重新包装成球探报告。
34. 作为资料维护者，我希望引用媒体、图片和底层比赛数据不自动继承文章正文许可，从而避免误把第三方材料纳入资料库。
35. 作为资料维护者，我希望来源特定的内容排除规则在解析时生效，从而保证通用解析能力不会越过实际准入范围。
36. 作为资料维护者，我希望每次正文或解析规则变化生成不可变版本，从而能够区分旧结论与新资料。
37. 作为资料维护者，我希望检索文本可以加入可追溯标题和实体信息而保留原文，从而同时改善召回与引用准确性。
38. 作为资料维护者，我希望暂存索引构建失败时旧活动版本继续可用，从而不会让一次导入破坏已有检索。
39. 作为资料维护者，我希望验证完成后一次发布新资料版本，从而不会向用户暴露只有部分内容的构建结果。
40. 作为资料维护者，我希望重建向量或全文索引后旧引用仍定位到同版原文，从而能够维护索引而不破坏案件证据。
41. 作为资料维护者，我希望运行时只有一份有效来源策略，从而不会因声明文件与数据库状态冲突而恢复已经撤回的内容。
42. 作为资料维护者，我希望撤回权限后新检索、缓存和旧引用解析共同遵守新策略，从而及时停止后续不允许的处理。
43. 作为资料维护者，我希望原文已不能继续留存时返回明确失效状态，从而完成资料处置而不伪称所有历史副本都已擦除。
44. 作为运行维护者，我希望本地模型和索引在调查前完成准备，从而使首次用户请求不临时下载模型或隐式重建语料。
45. 作为运行维护者，我希望复用现有聊天网关而保持 embedding 本地运行，从而减少新的部署依赖。
46. 作为运行维护者，我希望重排使用独立任务和有限候选集合，从而能分别控制其上下文、耗时和模型用量。
47. 作为运行维护者，我希望模型返回的陌生或重复引用标识被拒绝，从而不能由重排生成原文中不存在的资料。
48. 作为运行维护者，我希望外呼发出但完成状态未知时有可恢复记录，从而在进程重启后不自动再次调用同一重排。
49. 作为运行维护者，我希望超时返回不依赖底层本地计算可以协作取消，从而使用户可见的等待预算真实有效。
50. 作为运行维护者，我希望检索和重排的耗时、模式、原因及 token 覆盖分别可观察，从而能够定位延迟与质量问题。
51. 作为运行维护者，我希望常规日志不包含密钥、完整私有原文或隐藏推理，从而能够安全地检查运行记录。
52. 作为评审者，我希望收到问题、候选原文、最小支持区间和评分表，从而能够核对回答与引用而不承担观赛数据采集。
53. 作为评审者，我希望方法资料和历史球员资料分别统计结果，从而不会让一条路线的表现掩盖另一条路线的缺口。
54. 作为评审者，我希望校准与冻结验证按问题家族隔离，从而能够看出规则是否只记住了调参问题。
55. 作为评审者，我希望分别比较旧方案、混合检索基线与网关重排，从而能够判断新增调用是否带来实际收益。
56. 作为评审者，我希望模型自评分、作者标注、用户复核和独立复核被准确区分，从而不会把自动检查称为独立人工证据。
57. 作为评审者，我希望无答案、错误身份和历史范围干扰也进入评测，从而能发现看起来流畅但依据不成立的回答。
58. 作为项目展示者，我希望真实历史案例有可执行的检索与报告资料验收路径，从而能够展示实际证据链而不伪造当前候选。
59. 作为项目展示者，我希望试点限制和未完成的人工判断被明确记录，从而不会把小样本结果宣传为一般推荐质量或完整现役覆盖。
60. 作为维护者，我希望索引重建和不兼容数据格式有明确操作说明，从而能够采用新设计而不承担旧索引和旧 RAG 引用迁移工作。

## Implementation Decisions

- **模块职责与主要接口。** 升级现有知识检索接口为一个知识证据模块，公开检索与引用解析两项能力，分别使用 `retrieve` 和 `resolve`。内部封装准入、版本、混合检索、上下文、预算和有效策略；Agent 不需要理解数据库查询或重排实现。管理性的导入、发布、撤回与索引构建和 Agent 只读能力分开。
- **权威与派生存储。** SQLite 保存来源有效策略、不可变文档版本、原文块、发布记录及必要的检索幂等/外呼记录；LanceDB 保存可重建的全文与向量索引。知识库与现有长期用户偏好、招募案件 checkpoint 继续分别治理。
- **唯一有效策略。** 可审阅来源声明是显式导入与发布的输入，SQLite 中的有效策略是运行时唯一依据。重启或重新读取旧声明不能静默恢复已撤回权限，策略变更使相关缓存失效。
- **发布一致性。** 先准备暂存文档和派生索引，再验证文档、引用和索引一致性，最后通过权威目录事务切换活动版本。暂存失败不参与查询、不破坏当前活动版本；旧引用所需且仍允许留存的原文版本不依赖活动索引存在。
- **不可变资料与定位。** 文档版本由原始内容、规范化/解析规则和来源身份确定。原文块保留章节、段落序号与文本；持久引用包含文档版本、原文块、起止区间及文本 hash。区间按同一不可变 JavaScript 字符串的 UTF-16 code unit 计算，不能只存当前向量表的行标识。
- **元数据。** 保留资料类别、来源、作者、许可和署名、原始链接、语言、发布时间，以及可获得的球员身份、比赛、赛事/赛季、观看或分析样本范围。未知时间与身份保持未知，文档发布时间不能替代比赛时间。
- **原文与检索文本。** 原文用于引用，检索文本可加入可追溯的标题、章节、核验实体及样本信息。模型生成的摘要或解释不回写原文；初版不采用 LLM 为全部片段生成背景前缀。
- **结构感知切块。** 支持获准论文 XML、Markdown/文本分析资料与已有结构化观察资料格式，保留标题、段落、列表和完整句子。起始子块目标 200–350 个 E5 tokens，检索前缀计入模型窗口，最多重叠一个短段落并避免跨不相关章节；长度是可测量的工程起点。
- **来源特定规则。** 来源不允许的图表、补充材料、参考文献和另行归属的第三方内容不进入索引。通用解析器支持某种结构不改变该来源的许可范围，元数据发现不自动触发抓取与入库。
- **首批外部资料。** 使用项目已登记、通过 PLOS 官方 Search API 获取且正文声明 CC BY 4.0 的 Mead、O’Hare 与 McMenemy 论文（DOI `10.1371/journal.pone.0282295`）。球员资料限于作者对 La Liga PlayeRank 结果中 Ronaldo、Messi 等具名球员的研究解释；全文说明模型所用联赛比赛样本为 2017/18 赛季，但该段没有逐人标出具体比赛日期。不得把论文引用的 Wyscout、Transfermarkt/Kaggle、FBref 或 ClubElo 数据作为已经准入的材料，也不将论文全篇归为球探报告。SAGE 的 Evers 等论文另有 AI/RAG 使用许可条件，本项目没有取得该项许可，不进入首版。
- **检索前置过滤。** 从服务端访问上下文、当前有效策略和资料版本编译两路召回的筛选条件，在候选形成前排除无权或不适用资料。重排、上下文加载及报告交付前再次检查当前策略，避免并发撤回后继续使用已取得候选。
- **主体与样本。** 球员定性资料仅与已核验身份或精确来源标识关联，不按相似姓名合并。逐主体记录结果，预算未覆盖者标为未处理。历史资料仅按其真实样本使用，不能满足必须依赖近期比赛的判断。
- **原生混合检索。** 使用 LanceDB 原生全文 BM25 与向量查询及经过验证的中英文 ICU 分词，不将全部正文加载到内存重新计算词项分数。起始每路 Top 30，RRF 常数 60，融合去重后最多 12 条供重排，最终方法片段最多 6 条；数量可根据冻结评测和预算调整。
- **跨语言与片段准入。** 移除将中文查询词覆盖比例强制套用到英文原文的旧来源级门槛，在片段层校准相关性与拒答。方法与球员资料使用各自校准配置，一条相关片段不能让同来源其他片段自动通过；旧相似度和词项覆盖数字不沿用为新版标准。
- **查询处理。** 首版直接使用当前问题和明确条件，可补充经过审核的双语专业术语；不默认增加模型翻译、查询改写或多跳规划调用。身份、否定、数字和时间要求不能因查询扩展而静默放松。
- **网关复用。** 沿用现有聊天网关、模型配置和模型调用适配能力承担生成与重排，embedding 使用本地 multilingual E5。新增重排是独立的结构化相关性任务，不能使用 Planner 的足球动作提示词，也不要求网关提供 embedding 或专用 rerank 端点。
- **重排协议。** 初版每个用户回合最多一次新增批量重排，输出只包含给定候选的标识、顺序和有限相关性标签。非法 JSON、陌生/重复标识、集合不符、上下文超限、模型故障或超时均不能被修补成成功证据，也不触发额外模型修复循环。
- **重排不是事实核验。** 模型的相关性标签不能证明原文事实或当前能力。原文范围、作者观点和核实状态继续保留，程序的引用存在性/身份/范围检查也不能替代人工语义支持判断。
- **共享等待预算。** 每次用户输入引发的调查回合共享累计 15 秒额外 RAG 等待，涵盖 embedding、索引查询、重排、原文加载和上下文组装，排除原本 Planner 的生成时间。新用户回合才重置预算；同回合重试、多个资料查询和 checkpoint 恢复都继承已消耗额度。
- **预算内分配。** 初始重排等待上限取剩余额度与 8 秒的较小值，并为返回保留余量；没有剩余额度就不发起新外呼。模型准备、权重下载与资料构建在调查前完成，不在首个用户请求中隐式进行。候选数、子预算与额外调用的用量全部可观察，供应商或 SDK 重试不得绕过总预算或调用次数。
- **真实限制调用方等待。** 不把 await 前后检查取消信号等同于 15 秒上限。使用不阻塞请求处理的隔离执行及截止时间竞争，或经证明满足同等契约的适配方式；超预算后及时返回可用基线或不可用结果，丢弃迟到结果，阻止后续工具/报告更新。底层不可中断计算可能稍后结束，不能声称已经实际停止。
- **基线降级。** 重排失败只允许回退到独立验收通过、适用于当前语料与检索版本的混合基线。基线不可用或没有通过验收时返回明确不可用状态，不能使用未经确认的替代结果。降级只改变排序模式，不豁免来源、身份、时间和片段要求。
- **持久外呼与幂等。** 每个回合的预算消耗、重排已预约/已发出状态和完成结果必须可恢复；外呼前记录发出标记。响应提交前进程退出时保留完成未知状态，同回合不自动重发。不依赖只有成功结果的缓存，也不让进程内临时 context 成为恢复依据；同请求复用已完成引用但仍重新检查策略。
- **图状态与模型上下文。** 招募工具适配器调用知识证据模块，checkpoint 保存证据引用、结果摘要、排序模式、trace、版本及预算摘要；有效策略与预算记录各有唯一权威。原文按需加载，不重复将整批正文堆积到消息历史或 checkpoint。
- **解析与撤回。** 恢复案件、再次提供模型上下文和交付引用前重新解析。索引或切块重建后引用仍定位到同版不可变原文；原文失效、hash 不一致、权限撤回或版本不可得时返回明确状态，不自动换成最新文档。处理权限撤回先阻止新使用，索引清理后续进行；留存要求变化时处理原文并保留允许的最小失效标识，不宣称逻辑删除已经安全擦除所有历史字节。
- **报告与结果契约。** 保留未触发、未覆盖、未处理、成功未命中、取得资料、超时/故障和资料失效的可区分状态，逐主体反映真实覆盖。报告保留作者、来源类型、时间、样本、引用和限制，观点冲突分别展示。定性资料可支持人工考察优先级与说明，不产生新的比赛指标、百分位或客观能力总分。
- **历史试点接入。** 提供真实历史原文的可执行证据检索及报告资料投影验收，并核验招募工具适配器对主体和样本的处理。当前候选池无对应球员时正确返回未覆盖；不为产生命中增加历史球员、不扩张候选发现、不默认新增通用问答界面。
- **观察与私有资料。** 原有第一方观察仍使用独立保存和 AI/RAG 同意及来源类型，不把用户记忆、私有偏好混入共享资料。可选在线搜索保持与已入库资料不同的来源与治理语义，搜索结果不自动入库。
- **可观察性。** 记录各阶段耗时、结果计数、引用、索引/检索配置版本、重排模式、降级原因和实际模型 token 覆盖；缺失用量保持未知。默认记录避免密钥、完整私有正文、原始提示词和隐藏推理，不将检索计数或相关性分数解释为球员能力置信度。
- **不兼容处理。** 直接重建新索引和引用格式，明确区分旧数据并给出重新构建/新建受影响案件的操作说明。保留仍可展示的既有历史成品报告，与禁止旧资料进入新模型上下文分别处理；不承诺远程擦除浏览器已保存的副本。

## Testing Decisions

- **测试外部行为。** 好的测试通过公开操作观察返回的证据、来源、身份/范围、排序结果、失败状态、预算和可恢复行为；不绑定私有辅助函数、内部节点拆分、数据库表布局或旧阈值实现。文档的工程起始参数只能作为明确预算契约测试，不能代替效果标签。
- **一个主要测试面。** 主测试面是升级后的知识证据接口 `retrieve/resolve`。通过公开管理操作准备并发布资料，使用真实临时 SQLite 和 LanceDB，注入确定性 embedding、网关和可控时钟，避免为每个解析/排序小函数制造新的外部测试接口。
- **少量最高层接入验证。** 在现有招募 HTTP JSON/SSE 回合入口验证按需触发、资料引用进入报告、幂等、取消和恢复；只覆盖连接处的重要行为。检索质量和生命周期规则集中在知识证据模块，不在每层重复同一组断言。
- **许可与解析先例。** 沿用现有 knowledge、knowledge-permissions 与 PMC/PLOS 来源测试的行为范式：拒绝未登记来源、验证取得/存储/AI 处理范围、保留署名、遵守内容排除和同实例权限变更。新版验证两路召回及捕获到的网关请求均不包含禁止片段，源策略撤回后缓存与恢复也不能继续使用。
- **原文与引用。** 用含中文、英文、emoji、标题和前置定义的资料验证准确原文区间、hash 与上下文。导入新正文、改变切块或重建索引后旧引用仍返回旧原文；正文缺失、hash 错误或权限失效时不换新内容。构建中途失败仍可读取旧活动版本，发布后引用可解析。
- **检索与覆盖。** 验证方法与球员语料分开、中文查英文不因无共享词自动拒绝、相关性按片段判断、同名主体隔离、历史范围保留以及多主体结果不被全局截断误报为零命中。用标注样本检验采用/拒答规则，不复制旧相似度常数的测试。
- **重排协议与降级。** 注入有效排序、非法 JSON、重复/未知 ID、遗漏候选、服务故障和超时，验证模型不能增加或改写原文，只有已验收的对应基线可被采用；基线未经验收或版本不适用时明确不可用。记录实际排序模式和原因，权限/范围检查在所有模式均成立。
- **15 秒累计等待。** 用可控时钟驱动方法与球员检索连续消耗同一预算，验证剩余额度限制重排子预算，耗尽后没有新增模型调用；新用户回合才重置。对非协作式假推理/索引工作验证调用方按期返回且迟到结果不变更案件、进度、报告或调用其他工具，不将该测试描述为底层计算及时中止。
- **幂等与未知外呼状态。** 验证重复请求、图重试和重启恢复不重复已完成或已发出但完成未知的重排，并延续已用预算。通过外呼已记录、响应未提交的恢复场景验证这一点，不能只测试成功缓存命中。
- **暂停、取消和关闭重开先例。** 复用 native-runtime-policies、service-drain、checkpoint-recovery、recruitment-cancellation 的公开案件/HTTP 范式，使用真实 SQLite 关闭重开。验证引用在恢复后重新授权，预算不加回，取消与超预算/服务排空保持不同终态。
- **工具与报告先例。** 沿用 recruitment-tool-executor、recruitment-http、methodology-reuse-ablation 的适配与续案行为，以及现有 Web Search 整图用例中“定性线索不填补指标缺口”的不变量。历史试点可通过证据模块和报告投影验收，不以修改当前候选池为条件。
- **试点质量评测。** 准备 20–30 个问题，起始建议合计 24 个、两路各 12 个；每题记录主体、样本时间、最小支持原文和可回答/无答案标签，按问题家族隔离校准与冻结验证。比较旧方案、原生混合基线和新增网关重排的候选/最终片段召回、排序、无答案误接受、人工引用支持、耗时及 token 用量。
- **真实评测与自动回归分开。** 确定性 CI 不抓取外网、不下载模型、不访问真实网关；本地真实 embedding/已配置网关与获准语料的有界评测单独记录。人工判断在实际完成前保留待复核状态；独立评审是期望增强，不是用户已经承诺提供的先决条件。小样本和单篇/少数球员限制随结果报告，不使用模型自评分冒充人工证据。
- **验收证据。** 自动回归与构建通过只证明行为合同；质量结论还需真实检索数据和约定的人工复核。降级基线必须单独校准并通过冻结验证，不能因重排路径通过而视为基线也通过；未被用户采用的通用百分比目标不列为既定通过率。

## Out of Scope

- 当前球员市场、全部现役候选或近期比赛报告的完整覆盖，以及球员排序准确率或转会可行性保证。
- 由用户采集第一方观赛记录作为本次交付依赖；模型生成观赛事实、给未观看比赛打档或伪造原文。
- 将历史研究者观点称为当前球员能力、职业球探意见，或把论文署名许可扩展到其引用的媒体、图片和上游比赛数据。
- GraphRAG、RAPTOR、递归摘要树、目录浏览 Agent、全库 LLM 上下文前缀、默认在线翻译/多跳改写及模型微调。
- 新部署的本地 Cross-encoder、依赖网关新增 embedding/专用 rerank 端点、远程 embedding 迁移。
- 把知识证据模块再实现成独立 LangGraph/自主 Agent，或重构整个招募 Planner、候选数据仓库及无关调查策略。
- 为展示历史命中而扩张当前候选发现，新增通用问答 UI、引入新前端工作台或改造全部第一方观察录入体验。
- 多租户权限平台、分布式锁、微服务、集群伸缩或通用文档管理平台。
- 兼容旧向量索引、迁移旧 RAG 引用/全文 checkpoint，以及保证远程擦除浏览器历史报告或全部磁盘历史版本。
- 未取得许可的批量抓取、自动联系发布方、采购付费语料或把未准入网页搜索摘要自动转成索引资料。
- 本次规格发布不执行功能实现、真实模型调用、语料入库或人工评分；这些均属于后续实施与验收工作。
