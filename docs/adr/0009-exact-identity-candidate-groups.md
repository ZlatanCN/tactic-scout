# 用精确身份映射对候选来源记录分组

## Status

Accepted

## Context

多来源候选池会为同一球员保留不同 provider 的来源记录。按姓名或相似字段合并会造成错配；完全不识别精确映射又会让同一人以多个候选重复推荐。身份与表现是不同事实：跨来源 identity bridge 可以回答“是否同一人”，不能回答“指标口径是否可比”。

当前 Reep release 提供 Understat 精确 player ID bridge，但没有 ASA bridge。应用需能使用可验证映射消除重复候选，同时把缺桥接的 ASA 记录保持为独立记录并明确显示覆盖缺口。

## Decision

- 只在 resolver 对来源 provider 与原生球员 ID 返回唯一、有效的 Reep ID 时，将多条记录放进同一个候选身份组。
- 组内仍保留各自完整的来源记录、表现指标、样本、时间与出处；评估、百分位比较、证据引用和评分都按来源记录分别完成。
- 缺少稳定来源 ID、无精确映射、有歧义、受限/撤销映射或本机注册表不可用时，各记录继续单独成组，并报告具体解析状态。
- 分别汇报身份组数和来源记录数。Planner 可据此避免重复调查或提名同一已解析身份；Reviewer 拒绝同一身份组重复推荐。
- 案件级需求能力覆盖以候选身份组为分母；组内任一独立评估的来源记录包含所需指标，就计为该候选有覆盖。该摘要只统计指标可用性，不能将组内的指标值、评分或来源证据合并。
- Reep 只提供身份关系，不提供表现或当前效力事实。身份分组不会扩充数据源实际覆盖，也不会创建统一跨来源实力分数。

## Consequences

- Understat 等有精确 bridge 的记录可以按同一稳定身份归组，候选列表不重复显示同一个已验证身份。
- ASA 在当前 release 中仍无 bridge，因此不能据此消除它与 Understat 的潜在重叠；同名记录不作推断。
- UI 和报告必须同时展示身份解析与来源表现证据，且不以身份组计数冒充来源记录数。
- 需求能力覆盖的人数分母与报告评估候选数一致；来源记录数仍由独立字段表达。
- 评估 peer group 仍按 provider、来源赛事 ID、来源赛季 ID 和位置隔离。身份相同不代表同一口径。
- 本决策细化 [ADR 0006](0006-source-preserving-current-player-mosaic.md)：候选身份层可以分组，底层来源记录始终独立保留。

## Alternatives considered

- 按姓名、球队名或数值相似度合并：会把身份猜测伪装成事实。
- 完全不使用跨来源映射：会让已精确关联的同一身份重复进入候选和推荐。
- 将组内统计聚合成统一数值：不同 provider、赛事、赛季与指标定义并不天然可比，也会丢失证据出处。
