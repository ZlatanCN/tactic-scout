# 用受约束的 LangGraph 阶段编排球探调查

## Status

Accepted

## Context

球探案件需要让模型判断何时追问、要不要扩大候选范围，并在用户回答后继续同一案件。同时，候选筛选分页、比赛指标计算和报告检索有明确的顺序及证据边界。真实本地模型运行曾在报告检索完成后重复相同检索；候选分页、评估、报告工具预算之间也曾互相冲突，导致安全步数耗尽。

## Decision

LangGraph 保留 Planner 的案件级判断，并把不变量建模为独立工作阶段：候选页完成后，确定性策略评估有证据的候选批次，再检索尚未查过的已评估球员报告。报告检索按新增候选增量执行。

每批证据就绪后，Planner 进入显式结构化阶段：

- `expand`：只能读取来源返回的准确 `nextOffset`，并保留原筛选条件；也可以追问或基于当前样本结束。
- `reorient`：当前筛选范围已耗尽后，可改变用户未限定的搜索范围、追问或结束；不能重复报告检索或评估已评估候选。
- `conclude`：只能追问或提交由已评估球员与真实证据键构成的结论。

所有阶段都继续经过用户硬约束、来源错误处理、独立工具预算和最终证据复核。每轮安全步数必须覆盖这些工具预算及一个结束决策。

## Consequences

- Planner 仍可决定是否扩大样本、调整可放宽的范围或追问；确定性策略负责顺序和证据完整性。
- Cursor 与筛选范围进入结构化输出约束，减少模型重读页面或报告造成的无效调用。
- Harness 可以把每个 Planner 决策、策略动作、工具结果和 UI 进度生命周期逐项对照。
- 本地小模型的多阶段分析仍可能很慢；行为通过不证明推荐排序质量、数据代表性或长期稳定性。

## Alternatives considered

- 让模型在所有节点都从完整 action 集合自由选择：已暴露出重复报告检索、策略循环和工具预算冲突。
- 将候选扩展改成固定抓取全部分页：会把数据读取量和成本固定下来，也移除 Planner 根据证据决定是否继续采样的能力。
- 完全用确定性规则替代 Planner：不能根据用户回答、职责歧义和新证据灵活选择调查方向。
