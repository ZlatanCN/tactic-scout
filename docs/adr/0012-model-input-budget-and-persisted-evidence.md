# ADR-0012: Manage model input budgets independently of persisted evidence

Status: accepted

Implementation: ticket 01 ([all model inputs are budgeted](../../.scratch/runtime-context-management/issues/01-enforce-model-input-budgets.md)) is resolved. It adds shared model-input estimation, profile validation, finite ChatOpenAI output limits, context-limit failures, and complete result rendering after an interrupted explanation. Tickets 02–11 cover the remaining context selection, compaction, evidence batching, overflow recovery, and continuation work. The user confirmed Q1–Q15 and the complete plan in Q16 on 2026-11-08, with Q6 explicitly choosing automatic compaction. The accepted [plan](../../.scratch/runtime-context-management/plan.md), [published feature specification](../../.scratch/runtime-context-management/spec.md), and [technical detail](../../.scratch/runtime-context-management/design.md) continue to guide implementation.

Manage the complete input of every model call, including request understanding, the lookup model/tool loop, executed or saved-result explanation, and auxiliary context-processing calls. Check the prepared request before invocation, automatically process oversized content, and recover from provider-reported context overflow within bounded allowances.

Prepare a bounded model-facing working context while retaining complete messages and original tool results for traceability and preserving the validated workflow snapshots required by ADR-0010. Checkpoint retention, TTL, and storage reclamation are separate work. This lets later questions and recovery continue to use original evidence: reducing a prompt must not silently reduce the authoritative saved result or change confirmed player memory.

A single current result can exceed a model window even when conversation history is short, so a history-summary-only policy would not cover the existing input paths. Keeping prompt preparation separate from original evidence also avoids using lossy summaries as the source of exact identities, dates, ranks, or metrics. This decision extends runtime input handling without superseding the evidence and persistence ownership in ADR-0010 or ADR-0011.

Allow bounded additional calls to process oversized results and aim to complete the original request. If the configured limits still prevent completion, report the limitation and available continuation. Resolve window information from explicit configuration first, or from known model capability data for a trusted endpoint; require explicit configuration when the actual window is unknown, including unverified custom gateways. This adds a configuration requirement rather than relying on an assumed model window.

Use program-directed field/record selection, chunking, and source recovery for structured player evidence, with text summarization for conversational or process history. The first implementation keeps lookup's controlled search tool without adding a general model-selected context/file retrieval tool or a separate filesystem. An oversized current user input also triggers automatic compaction. First reduce older working context and retain the current user message verbatim when it fits; if that message itself exceeds the usable budget, process it in bounded chunks to produce a task/constraint representation with source locations. Original inputs are retained, and compaction calls themselves must fit their model's input budget. Validate exact references and known constraints; continuation evaluation additionally checks semantic fidelity.

Persist derived compaction results, their covered input ranges, source references, and version metadata with the thread checkpoint. Reuse a result only while it still matches the source input and applicable version, including after a normal restart. This auxiliary thread context does not belong in the cross-thread identity Store. An invalid auxiliary cache is rebuilt from original evidence; it does not by itself make the whole thread incompatible.

Keep the existing StateGraph and business routing. Share input-budget, compaction, and overflow-recovery capabilities across model entry points while each entry point defines its evidence selection rules. Use configurable initial thresholds of 80% of the usable input budget to trigger compaction and 60% as its target, with a separate hard-fit check before every invocation. Usable input accounts for the actual model limits, output reservation, and counting uncertainty. These percentages are tuning defaults, not measured guarantees or a requirement to discard necessary information to reach the target.

Use the configured task model and endpoint for summarization / chunk extraction by default; permit a separately configured compaction model with its own known limits. Add a shared per-request allowance, initially six additional model requests and 120 seconds of cumulative active context-processing time, stopping at whichever limit is reached first. Count failures and retries, retain consumption across restart / resume, and keep the existing node-retry and lookup-search caps. User-wait and service-downtime intervals do not consume active-processing time. This allowance bounds the expanded workflow rather than resetting whenever another node is entered.

When a complete validated data result exists but context processing or explanation is incomplete, render the complete data and provenance deterministically, in segments when needed, and explicitly identify the incomplete explanation. If task understanding or data acquisition is incomplete, report coverage and limitations without a whole-group comparison or ranking conclusion. Preserve committed results and recovery progress. A user explicitly requesting continuation after allowance exhaustion can grant a new bounded allowance; retain prior consumption, reuse completed work, and do not grant more merely because a thread restarts or resumes. Ambiguous or conflicting instructions still require clarification.
